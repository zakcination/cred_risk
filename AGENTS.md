# Правила GPT/Codex для `cred_risk`

Корневые правила проекта и конфиденциальности находятся в [`CLAUDE.md`](CLAUDE.md) и
обязательны для любой работы в репозитории.

## ВНД и НПА

Перед ответом, анализом или изменением, затрагивающим ВНД, НПА, IFRS, провизии,
пруденциальные нормативы, риск-аппетит, SREP, НСТ либо восстановление финансовой
устойчивости:

1. Прочитать [`docs/analysis/npa_registry/KNOWLEDGE_BASE.md`](docs/analysis/npa_registry/KNOWLEDGE_BASE.md).
2. Проверить документ, редакцию, статус и замену в
   [`REGISTRY.md`](docs/analysis/npa_registry/REGISTRY.md).
3. Проверить применимый пункт в [`CITED.md`](docs/analysis/npa_registry/CITED.md).
4. Для провизий дополнительно проверить
   [`PACKAGE_1_NPA_VND.md`](docs/analysis/provisions_method/PACKAGE_1_NPA_VND.md).
5. Использовать тематический маршрут из `KNOWLEDGE_BASE.md`, а предметный разбор не считать
   заменой первичного источника.

Каждый содержательный нормативный вывод должен содержать:

- стабильный `source_id`;
- пункт, приложение, страницу или иную точную координату;
- редакцию и дату действия;
- официальную ссылку для публичного НПА;
- ссылку на карточку или предметный разбор в репозитории;
- статус `ПОДТВЕРЖДЕНО`, `НЕ ПРИМЕНИМО`, `ОТСУТСТВУЕТ` или `ТРЕБУЕТ РЕШЕНИЯ`.

Если пункт не зарегистрирован, нельзя восполнять его по памяти. Если источники конфликтуют,
показывать обе версии и ставить `ТРЕБУЕТ РЕШЕНИЯ`; приоритет без решения владельца не
выбирать. Аналитический вывод, расчёт на данных и гипотезу всегда разделять.

Исходные тексты конфиденциальных ВНД, клиентские данные и банковские выгрузки в репозиторий
не помещаются. Для ВНД используются реквизиты, редакция, координата пункта и подтверждённый
разбор; нельзя утверждать, что GitHub содержит оригинал документа.
