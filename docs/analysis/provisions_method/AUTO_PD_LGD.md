# PD и LGD автопортфеля: декомпозиция расчёта

Заведён 23.09.2026. Предмет — как **по документам Банка** получаются PD и LGD
автокредитов (группа ПОЗ «авто», портфели 3 и 10 по Приложению 4.1 МСФО-методики),
из каких узлов состоит каждое число и какие решения нужно принять, прежде чем
воспроизводить его на данных.

Основа — разбор Методики в [`README.md`](README.md) § 2 и находки П-1…П-15. Здесь
ничего не доказывается заново: формулы взяты оттуда, со ссылкой на ячейку. Новое —
проекция на авто, дерево чувствительности и вопросы, без которых скрипт писать рано
(корневой `CLAUDE.md` § 6).

## 0. Сначала возражение: «PD и LGD по авто» — это не одна величина

У Банка **как минимум три разных** числа, которые называются «PD по авто» или
«LGD по авто», и они считаются разными методами:

| # | Величина | Документ | Метод | Что о ней известно |
|---|---|---|---|---|
| 1 | `PD_12`, `PD_LT`, `LGD` группы ПОЗ «авто» | МСФО-методика, Приложение 4, 4.3, 4.5 | поколения выдач, кривая возврата, TV | формулы таблиц — § 2 README |
| 2 | LGD по автотранспорту для стресс-теста | Методика стресс-тестирования, Приложение № 6 | кривая возврата + TV, три сценария | базовый 21,11 %, негативный 16,59 %, кризисный 29,94 % — немонотонно (`risk_appetite` Г22) |
| 3 | PD автокредитования в стресс-тесте | та же Методика, Приложение № 4 (макромодель) | регрессия на макрофакторы | 4,75 % / 6,16 % (базовый / кризисный); модель не идентифицируема (Г21) |

Отсюда первое, что надо решить: **что декомпозируем**. Этот документ разбирает
величину № 1 — она идёт в провизии и, по гипотезе Г-PM-1, в метрики риск-аппетита.
Величины № 2 и № 3 учтены там, где с № 1 их можно сверить (§ 4).

Второе возражение — к данным. Методика строит поколения **с 2012 года**
(Приложение 4, Раздел 1). В mart `loan_account` по S01 историзована на **19 дат с
2025-01-01** (`dict_registry/objects.csv`). Воспроизвести кривую 2012+ на mart нельзя;
это структурное ограничение, а не деталь плана сбора (§ 6, решение Р-А4).

## 2. Дерево PD

Единица наблюдения — заём; группировка — поколение выдачи `i = ГГГГММ`; время —
возраст `j` в месяцах от выдачи.

```
PD_PIT  ← PD × clamp(PIT)                                    4.8  (П-4, П-10)
  └─ PD_12', PD_LT'  ← p_m'                                  4.3 Result, стр. 89–91
       └─ S_k = S_obs × g^(k − n)                            стр. 87–88  (П-3)
            ├─ g  = GEOMEAN(1 − PD(j)), последние 6 мес.
            ├─ k  = Max Age продукта — из ВНД, не из данных  п. 7 б
            └─ S_obs = Π_j (1 − PD(j))                        стр. 79
                 └─ PD(j) = AVERAGE_i DR(i, j)                стр. 78
                      └─ DR(i, j) = D(i, j) / N(i, j)         Result
                           ├─ D: прирост дефолтов              'Default increment'
                           │    ├─ месяц дефолта: max(j; 3)    base!F2  (П-7)
                           │    └─ оздоровление обнуляет дату   п. 7 г  (П-5)
                           └─ N: недефолтные на начало j        'Non default'
                                └─ закрытие: max(j; 3)          base!G2
```

### 2.1 Что в каждом узле значит для авто

| Узел | Особенность авто | Статус |
|---|---|---|
| `D(i, j)` | Дефолт по п. 5. У авто типичный путь в дефолт — изъятие и продажа машины; если заём **закрывается** реализацией залога раньше 90 дней просрочки, он выбывает через `N` как закрытие, а не через `D` | гипотеза Г-AUTO-2 |
| `N(i, j)` | Досрочное погашение (перепродажа машины, рефинансирование) уменьшает `N`, не трогая `D`; `DR` условный, это корректно. При `max(j; 3)` закрытия первых трёх месяцев переносятся в третий. Насколько досрочка в авто велика — не измерялось | правило — документально (П-7); масштаб — разведка |
| `PD(j)` | Простое среднее по поколениям, **не взвешенное по числу выдач**. Малое поколение (например, период приостановки выдач) весит как большое | документально, 4.3 стр. 78 |
| `n` | Максимальный наблюдаемый возраст. Для поколений 2012 года к 2026 — до ~170 мес.; но наблюдение «хвоста» даётся единицами поколений | документально |
| `k` | Срок продукта из ВНД. **Для CAR CL п. 7 д фактически задаёт `k = n`** — экстраполяции нет | выведено из п. 7 б + п. 7 д; следствие — Г-AUTO-3 |
| `g` | Геосреднее выживаемости последних 6 наблюдаемых месяцев — то есть по **самым поздним возрастам**, где поколений меньше всего | документально (П-3) |
| PIT | Одна калибровка на все группы ПОЗ или отдельная по авто — из 4.8 не видно | В-AUTO-3 |

### 2.2 Чувствительность `PD_LT'` к `k` (выведено из формул 4.3)

    ln S_k = ln S_obs + (k − n) · ln g

Каждый месяц срока сверх наблюдённого умножает выживаемость на `g`. Если продукт
длиннее наблюдённой истории, `PD_LT'` определяется не данными, а парой (`k`, `g`),
где `k` — число из паспорта продукта, `g` — хвост на нескольких поколениях.
Если срок авто-программ укладывается в историю с 2012 года, `n ≥ k` и экстраполяция
не нужна; **если** же `k` у какой-то программы больше наблюдённого
`n` — это место, где число выдумывается формулой. Какие `k` стоят в паспортах
авто-продуктов — В-AUTO-2.

**Г-AUTO-3.** Правило п. 7 д для CAR CL («как при завершённом цикле») при
незавершённом цикле означает `k = n < срока продукта`, то есть `PD_LT` считается
по неполной кривой и **занижается** на неучтённую часть жизни. Проверяется одним
числом: максимальный наблюдённый возраст поколений CAR CL против срока продукта.

## 3. Дерево LGD

Единица наблюдения — **поколение дефолта** `i` (месяц выхода в дефолт); время —
`j` месяцев после дефолта.

```
LGD = LGD_noTV − mean_i(TV_i / EAD_i)                        4.5 result, стр. 86
  ├─ LGD_noTV = max(0; 1 − CumRR(n_max))                     стр. 85
  │    └─ CumRR(j) = Σ_{t≤j} AvgRR(t)                        стр. 83
  │         └─ AvgRR(t) = AVERAGE_i RR(i, t)                 стр. 82
  │              └─ RR(i, t) = min(R_disc / (EAD_i + C_i); 1)  F6  (П-1: C не подписан)
  │                   ├─ R_disc: платежи, дисконт по EIR к дате дефолта, курс V0/V
  │                   ├─ исключены: оздоровленные, ПОТОКИ ОТ ЗАЛОГА
  │                   └─ включены: платежи коллекторов
  └─ TV_i = Σ_p min(TV_disc_p; задолженность_p)               текст, этап 2 п. 4
       └─ TV_disc_p = Collateral_p × k_liq × k_price / (1+r)^t + Pledge_money_p
            ├─ k_liq   — по виду обеспечения                   4.4
            ├─ k_price — по региону, типу, месяцу выдачи;     4.4 а  (П-6: #REF!)
            │            для авто отрицательные значения
            ├─ t ≥ 0,5 года — срок взыскания
            └─ реализованный залог — по цене реализации
```

### 3.1 Что в каждом узле значит для авто

| Узел | Особенность авто | Статус |
|---|---|---|
| Разделение потоков | Возврат от залога **исключён из `RR`** и идёт через `TV`. Для авто это главная часть возврата. Если выручка от продажи машины зачислена на счёт займа как обычный платёж, в `R_disc` она **неотличима** от платежа заёмщика — и засчитывается дважды: в `RR` и в `TV` по цене реализации | гипотеза Г-AUTO-4; как размечена выручка от залога в RS — В-AUTO-4 |
| `k_price` для авто | «Отрицательные значения, то есть обесценение» (README § 2.3). Формула `Collateral × k_liq × k_price` при **отрицательном** `k_price` даёт отрицательный TV, т. е. залог **увеличивает** LGD. Либо в таблице стоит изменение стоимости (−x %), а в формулу идёт `1 + k_price`, либо формула работает неверно | противоречие между таблицей и текстом; В-AUTO-5 |
| `k_liq` для авто | Известно только для недвижимости (0,7). Для авто — не зафиксировано | В-AUTO-5 |
| `Collateral_p` | Оценка на дату выдачи или последняя переоценка? Для авто разница за 3–5 лет — десятки процентов | В-AUTO-5 |
| `mean_i(TV_i / EAD_i)` | Вычитается **среднее по поколениям дефолта** отношение, а не TV текущего портфеля. LGD для корзин 1–2 получает залоговую поправку по историческим дефолтам — это и есть модельная суть | документально |
| `n_max` | Окно возврата. Незавершённые поколения входят в `AvgRR(t)` только до своего возраста — суммирование средних по разным наборам поколений | документально; метод — § 6 Р-В3 |
| Оздоровленные | Исключаются из `RR` и из дефолтов PD (п. 7 г). Внутренне согласовано: PD считает только неоздоровившиеся дефолты, LGD — только их потери. **Согласовано, только если определение оздоровления одно и то же в обоих местах** | гипотеза Г-AUTO-5 |
| `C_i` | Неподписанный столбец знаменателя | П-1 |

### 3.2 Сверка с Приложением № 6 стресс-теста

Приложение № 6 — отдельный расчёт LGD по автотранспорту, по той же схеме
«кривая возврата + TV». Известные числа (`risk_appetite/FINDINGS_RA.md` Г22, МС1–МС3):

| | Базовый | Негативный | Кризисный |
|---|---|---|---|
| LGD итоговый | 21,11 % | 16,59 % | 29,94 % |
| LGD without TV, строки 86–88 | 44,82 % | 50,46 % | 50,46 % |
| LGD without TV, строка 97 | 45,15 % | 44,82 % | 50,21 % |

Арифметика, не проверенная по формулам листа: при первом наборе поправка за залог
`LGD_noTV − LGD` ≈ 23,7 пп в базовом сценарии и ≈ **33,9 пп в негативном** — то есть
в негативном сценарии залог «стоит» больше, чем в базовом. Это другая запись той же
немонотонности Г22. **LGD Приложения 4.5 и LGD Приложения № 6 — это одно и то же число
в разных ВНД или два разных расчёта?** Если одно — стресс-LGD наследует все узлы § 3;
если два — у Банка две LGD по авто на одном портфеле (В-AUTO-6).

## 4. Сборка в провизии — где PD и LGD встречаются

Из 4.2 (README § 2.5):

| Корзина | Провизия | Какие узлы авто работают |
|---|---|---|
| 1 | `V × PD_12 × LGD` | весь § 2 до `PD_12'`, весь § 3 |
| 2 | `V × PD_LT × LGD` | § 2 с экстраполяцией — здесь срабатывает Г-AUTO-3 |
| 3, генерация `m` | `max(V(m) − ER(m); 0)`, `ER = min(Bal; TV_m + Σ_{j≥m} AvgRR(j) × EAD_m)` | `AvgRR` из § 3 и TV **текущего** залога |

В корзине 3 TV входит залогом **конкретной генерации**, в корзинах 1–2 — историческим
средним. Значит, падение цен на авто бьёт по корзине 3 через `k_price` сразу, а по
корзинам 1–2 — только по мере того, как новые дефолты войдут в историю TV.

## 6. Что нужно решить до скрипта (§ 6 корневого CLAUDE.md)

Ниже — альтернативы, не выбор. Выбор за автором.

### Шаг 1. Структурный подход

| Решение | Варианты | Довод со ссылкой |
|---|---|---|
| **Р-А1. Цель** | (а) **воспроизвести** Методику как написана — проверка реализации; (б) **challenger**: независимая оценка тем же данным другим методом — проверка модели | (а) — то, что делает внутренняя валидация по IFRS 9 B5.5.52 (регулярный пересмотр методологии и допущений); (б) — EBA GL/2017/16 гл. 5–6, стандарт оценки PD/LGD, в т. ч. ретейл |
| **Р-А2. Единица наблюдения** | заём / заёмщик | Методика — заём. CRR ст. 178(1), последний абзац, допускает определение дефолта на уровне отдельного обязательства для розницы |
| **Р-А3. Определение дефолта** | п. 5 Методики целиком / только 90+ | п. 5 — для воспроизведения; 90+ — если триггеры смерти/банкротства не размечены в данных |
| **Р-А4. Окно наблюдения** | поколения 2012+ (как в Методике; нужен OLD или архив RS) / 2025+ (только mart; для PD_LT непригодно, для `DR(i, j)` на ранних возрастах — пригодно) | Методика, Раздел 1; ограничение mart — `dict_registry/objects.csv` |

### Шаг 2. План сбора — что сначала разведать

Имена колонок — только из живого аудита (§ 4). До плана сбора предлагается
**разведочный прогон** (не скрипт расчёта):

1. Глубина истории по периметру авто в mart и в OLD (`PORTFOLIO_RS`, `CL_PORTFOLIO_2`):
   min/max дата среза по источнику. Решает Р-А4.
2. Поля, которыми авто выделяется: `loan_obj`, продукт / подпродукт, вид обеспечения
   (в `dict_registry/fields.csv` для S01 имя не зафиксировано). Решает Г-AUTO-1.
3. Покрытие `pledges` для авто: доля займов с залогом, заполненность оценки и даты
   оценки (`c_car_brand` — свободный текст, E28). Решает, считаем ли TV.
4. Домен `source` в `writeoff` / `collections` / `Offbalance` — **только S01/S03**
   (FINDINGS сверки). Если авто живёт в другом источнике, возвраты после дефолта
   в mart не видны вовсе.

### Шаг 3. План обработки — фиксируется до прогона

| Решение | Варианты |
|---|---|
| **Р-В1. Усреднение `DR` по поколениям** | как в Методике (простое) / взвешенное по `N(i, j)` |
| **Р-В2. Правило `max(j; 3)`** | сохранить (воспроизведение) / снять и показать эффект (П-7) |
| **Р-В3. Незавершённые поколения возврата** | как в Методике (сумма средних) / только завершённые / оценка хвоста (EBA GL/2017/16, гл. 6 — incomplete recovery processes; пункт уточнить по тексту) |
| **Р-В4. Критерий подтверждения** | для воспроизведения — расхождение с числом УКРР на ту же дату в пределах допуска, допуск задать до прогона; для challenger — направление и величина отклонения, с интервалом |

Что считается подтверждением каждой гипотезы § 5 — записать в эту таблицу **до**
прогона, иначе любой результат окажется подтверждением.

## Что доказано, что взято из документа, что гипотеза
