## 2. Что документ говорит дословно

### 2.1. Таблица 3 (стр. 13–14) — периметр расчёта

Ключевые строки для кредитного риска:

| Портфель | Кредитный риск | ЧПД |
|---|---|---|
| Индивидуальные займы | **распределены по другим портфелям** | анализируются |
| Займы, переданные в ОУСА | **распределены по другим портфелям** | не анализируются |
| Займы с государственной поддержкой | **распределены по другим портфелям** | анализируются отдельно |
| Дебиторская задолженность | не анализируется | не анализируется |
| Займы финансовым институтам, госструктурам | не анализируются | анализируются |
| Остальные 11 портфелей | анализируются | анализируются |

По анализируемым портфелям дословно: «Анализируются все портфели — стартовая
точка НСТ должна быть скорректирована на результаты AQR».

**Следствие:** `Individual loans`, `DISASS` и господдержка **не являются
конечными значениями сегмента** для кредитного риска. Это признаки, которые
сосуществуют с продуктовым портфелем.

### 2.2. Таблица 4 (стр. 14–15) — критерии отнесения

Оговорка п. 29 дословно:

> «Для отнесения активов к тому или иному портфелю используются критерии AQR,
> приведенные в Таблица 4. **При этом первичная сегментация выполняется в рамках
> AQR и может отклоняться от приведенных ниже критериев.**»

Критерии по сегментам:

| Сегмент | Критерий дословно |
|---|---|
| `CORINV` инвестиционные | срок ≥ 5 лет **и** запрет полного досрочного погашения **и** юрлицо **и** бизнес-план на создание/расширение/модернизацию материального производства. Исключение: не относятся займы на приобретение и строительство недвижимости |
| `COREST` недвижимость | **«Согласно требованиям регуляторной отчетности»** |
| `CORGOV` госкорпорации | ФНБ «Самрук-Қазына», НУХ «Байтерек», НУХ «КазАгро» + их дочерние + дочерние дочерних с госучастием > 50 %. «Все займы **вне зависимости от их назначения**» |
| `CORLAR` крупный | ст. 24 п. 6 ПК РК: > 250 работников **и (или)** доход > 3 000 000 МРП. Кроме инвестиционных и недвижимости |
| `CORMED` средний | ст. 24 п. 5 ПК РК: не малое **и** не крупное. Кроме инвестиционных и недвижимости |
| `RETSML` малый | ст. 24 п. 3 ПК РК: ИП без образования ЮЛ и ЮЛ с ≤ 100 работников **и** доходом ≤ 300 000 МРП |
| `RETEST` ипотека ФЛ | **«Согласно требованиям регуляторной отчетности»** |
| `RETCAR` авто и прочие обеспеченные ФЛ | **«Согласно требованиям регуляторной отчетности»** |
| `RETCON` потребительские ФЛ | **«Согласно требованиям регуляторной отчетности»** |
| `RELATE` ЛСБОО | **«Согласно требованиям регуляторной отчетности»** |
| `DISASS` ОУСА | все займы на балансе ОУСА по амортизированной стоимости |
| Индивидуальные займы | «Все займы, общая задолженность которых **превышает** 0,2 % от собственного капитала Банка» |
| Дебиторка | вся, кроме требований банка к ОУСА |
| Господдержка | займы по программам из **параграфа 242** |

**Пять сегментов (69 % EAD) содержательного критерия не имеют** — отсылка
к регуляторной отчётности.

### 2.3. Какая именно форма — ответ найден

Инструкция к шаблону, **п. 6, стр. 5**, дословно:

> «Данные на отчетную дату заполняются согласно значениям в формах
> регуляторной отчетности (**700-N, отчет о выполнении пруденциальных
> нормативов, PORTF, INVEST** и иные отчеты), скорректированным на результаты
> AQR при их наличии.»

Инструкция, п. 148, стр. 60: соответствие статей формы 700-Н и сегментации НСТ
приведено в **приложении 1** — отдельный файл `Приложение 1. Соотнесение
сегментации НСТ и статей 700-Н.xlsx`, **которого у нас нет**.

**Вывод.** Эталон для пяти розничных и связанных сегментов лежит в формах
700-N / PORTF / INVEST. Розничное деление вероятнее всего задаёт **PORTF**
(форма по портфелям займов) — это **гипотеза Г1**, проверяется составом формы.
Приложение 1 закрывает вопрос напрямую и должно быть запрошено.

### 2.4. Таблица 5 (стр. 61) — важная находка про 200 млн

В перечне сегментов для **референсных ставок ЧПД** присутствует отдельный
сегмент, которого нет ни в Таблице 3, ни в Таблице 4:

> «**Крупные займы физических лиц (более 200 млн тенге)**»

**Следствие.** Порог 200 млн в розничной ветке скрипта — не выдумка скрипта,
у него есть источник, но **в контуре ЧПД, а не кредитного риска**. Для
кредитного риска такого сегмента Таблица 4 не содержит. Куда порог относится
в нашем расчёте — **открытый вопрос О5**.

## 3. Что доказано на данных

База: `AQR2025_B1A_2024_Q4` (731 159 договоров) + эталон `segment_afr`.
Метод: дерево решений на допустимых критериях Таблицы 4, режим `strict`,
точность 0,99742.

### 3.1. Эталон не содержит трёх значений

В `segment_afr` **отсутствуют** `Individual loans`, `RELATE`, `DISASS`.
Это прямое подтверждение Таблицы 3: АФР их распределяет.

### 3.2. Розница делится по `loan_obj`

| Правило | Строк | Чистота |
|---|---|---|
| `loan_obj = 8` (потребительские товары и услуги) → `RETCON` | 619 638 | 100 % |
| `loan_obj = 6` (автомобильный транспорт) → `RETCAR` | 103 341 | 100 % |
| `loan_obj = 1` (жилая недвижимость) → `RETEST` | 799 | 99 % |
| `loan_obj = 3` (коммерческая недвижимость) → `COREST` | 43 | 100 % |

Метка продукта критерием **не является**: `portfolio = 'Auto'` — 376 договоров,
из них **95 % эталон относит в `RETSML`**, а не в `RETCAR`.

### 3.3. `ent_type` с эталоном согласуется плохо

| `ent_type` | Строк | Куда относит эталон |
|---|---|---|
| `0` физлицо | 725 630 | `RETCON` 86 %, `RETCAR` 14 % |
| `3` малый | 2 849 | `RETSML` **72 %**, `CORMED` 21 %, `CORLAR` 4 % |
| `2` средний | 699 | `CORMED` **57 %**, `CORLAR` 27 %, `RETSML` 15 % |
| `1` крупный | 513 | `CORLAR` **58 %**, `CORMED` 41 % |

Розница — соответствие полное. Бизнес — 57–72 %. Дерево на корпоративных
сегментах правил с чистотой ≥ 80 % **не выделило вовсе**. 76 % подлинных
расхождений лежат на границе `RETSML` ↔ `CORMED` ↔ `CORLAR` в обе стороны.

### 3.3а. ИП с розничным займом — вторая ось ошибки

Замечание Sabila: ИП берёт потребительский заём. Куда он должен попасть?

`ent_type` и `debtor_se` — атрибуты **заёмщика**, `loan_obj` — атрибут **займа**.
ИП одновременно физическое лицо и субъект малого предпринимательства
(ст. 24 п. 3 прямо: «индивидуальные предприниматели без образования
юридического лица»). Наши правила выбирают сегмент по статусу заёмщика,
а не по назначению займа.

Механика: розничная ветка каскада требует `debtor_se = 0`. ИП её не проходит
никогда и проваливается в `ent_type = 3 → RETSML` — независимо от того,
оборотка это или потребительский заём.

**Масштаб: 1 206 договоров на 2024 Q4 — больше половины сегмента `RETSML`
(2 152).**

В разрезе по `ent_type` (п. 3.3) этот эффект **не виден**: там дрейф по размеру
(малый → `CORMED` 21 %, `CORLAR` 4 % — вверх), а эффект ИП толкает в розницу.
Это отдельный тип ошибки — **тип G**.

**Контраргумент против правки.** Таблица 4 определяет `RETSML` по субъекту
(«Займы субъектам малого предпринимательства») и **без оговорки о назначении**,
тогда как у `CORLAR` и `CORMED` оговорка «кроме инвестиционных и выданных
на приобретение, строительство недвижимости» стоит явно. Асимметрия намеренная.
При буквальном чтении любой заём ИП, включая потребительский, принадлежит
`RETSML`, и текущее поведение верно.

**Разрешается эталоном, а не текстом** — запрос Д4. Гипотеза **Г5**.

### 3.4. Справочники заполнены частично

## 6. Шесть типов расхождений с эталоном

| Тип | Причина | EAD 2025 Q4 | Решение |
|---|---|---|---|
| **A** | флаг (`Individual loans` / `RELATE` / `DISASS`) выдан вместо продуктового сегмента | 31,22 % + 2,03 % | Р1 — флаги отдельными колонками |
| **B** | розница делится по `collateral` / `portfolio`, а эталон — по `loan_obj` | до 62,4 % переклассифицируется | Р2 — `loan_obj` |
| **C** | `ent_type` не согласуется с эталоном на 28–43 % | 4,59 % | Р3 — оставить как есть, писать в записку |
| **D** | фильтр `loan_purp IN (1,2,3,4,5,8)` пропускает 99,5 % и ничего не отсекает | ~0,01 % | снят |
| **E** | порог EAD 200 млн — источник в Таблице 5 (ЧПД), не в Таблице 4 | измеряется | Р4 — смотрим по эталону, запрос Д1 |
| **F** | 317 415 строк выгрузки без эталона, недостаёт 1 467 договоров против B1A | — | считается на SQL, запрос Д3 |
| **G** | ИП с розничным займом уходит в `RETSML` по статусу заёмщика, а не по назначению займа | 1 206 договоров = >½ `RETSML` | решается запросом Д4, гипотеза Г5 |

Типы C и G — разные оси на одной границе. C — дрейф по **размеру** бизнеса
(`RETSML` ↔ `CORMED` ↔ `CORLAR`), внешними данными не закрыт и скриптом
не лечится. G — дрейф по **назначению** займа (`RETSML` ↔ `RETCON`/`RETCAR`),
и он, в отличие от C, **может оказаться исправимым без внешних данных**.
Поэтому Д4 прогоняется до того, как ошибка `ent_type` объявляется
окончательной: часть её может оказаться ошибкой типа G.

## 6а. Принятые решения

**Р1. `Individual loans`, `RELATE`, `DISASS` — колонки-флаги, не значения сегмента.**
Основание: Таблица 3 («распределены по другим портфелям») и отсутствие этих
значений в эталоне АФР. Сегмент всегда продуктовый. Флаги сохраняются рядом —
они нужны для ЧПД, где Таблица 3 требует их анализировать.

**Р2. Розница делится по `loan_obj` — рабочая версия.** Основание: эталон АФР
воспроизводится на 99–100 %. Таблица 4 критерия не даёт, форма (`PORTF`)
не получена, поэтому эквивалентность «`loan_obj = 1` ≈ обеспеченные жилой
недвижимостью» вносится в пояснительную записку как допущение **Г2**.
Приложение 1 запрашивается параллельно; при его получении правило сверяется.

**Р3. `ent_type` остаётся как есть.** Ни снимка РСП, ни годового дохода,
ни численности работников у нас нет — проверить статьёй 24 нечем.
Корпоративная часть считается с известной ошибкой 25–43 % и этот факт идёт
в пояснительную записку явным пунктом, а не умалчивается.

**Р4. Порог 200 млн решается эталоном, а не документом.** Запрос Д1 показывает,
куда эталон АФР 2024 Q4 отнёс займы ФЛ свыше 200 млн. Как поступил эталон —
так поступаем и мы. До прогона порог в правилах не участвует, но признак
`flag_retail_over_200m` считается всегда.

**Р5. Список Sabila (66 БИН) неприкосновенен.** 46 ненайденных БИН ищутся
в других кварталах `AQR2026` и в `B1B` (запрос Д2). Список не сокращается.

### С1. Сегментация 2025 Q4 — итоговый скрипт

Запускается **после** Д1, Д3 и Д4. Порог 200 млн в правилах не участвует
(решение Р4 до прогона Д1), но считается признаком.

**Розничная ветка ниже написана в текущей редакции — с `debtor_se = 0`.**
Это означает, что ИП в розницу не попадает никогда. Если Д4 подтвердит Г5,
условие снимается и заменяется разделением по назначению займа. До прогона Д4
скрипт считается предварительным.

```sql
SET NOCOUNT ON;
DECLARE @capital float = 503086114000;   -- СК на 01.01.2026
DECLARE @thr_ind float = 0.002;

WITH b1a AS (
    SELECT n.*
        , COALESCE(TRY_CAST(n.ead AS float), 0) AS ead_n
        -- задолженность по п. 44: без пеней и корректировки
        , COALESCE(TRY_CAST(n.od           AS float), 0)
        + COALESCE(TRY_CAST(n.od_del       AS float), 0)
        + COALESCE(TRY_CAST(n.interest     AS float), 0)
        + COALESCE(TRY_CAST(n.interest_del AS float), 0)
        + COALESCE(TRY_CAST(n.disc_prem    AS float), 0) AS amount
        -- база порога 0,2 %: как считает действующий расчёт AQR
        , COALESCE(TRY_CAST(n.od           AS float), 0)
        + COALESCE(TRY_CAST(n.od_del       AS float), 0)
        + COALESCE(TRY_CAST(n.interest     AS float), 0)
        + COALESCE(TRY_CAST(n.interest_del AS float), 0)
        + COALESCE(TRY_CAST(n.correction   AS float), 0)
        + COALESCE(TRY_CAST(n.disc_prem    AS float), 0)
        + COALESCE(TRY_CAST(n.penalty      AS float), 0) AS zadol
        , TRY_CAST(n.debtor_type AS int) AS debtor_type_n
        , TRY_CAST(n.debtor_se   AS int) AS debtor_se_n
        , TRY_CAST(n.ent_type    AS int) AS ent_type_n
        , TRY_CAST(n.loan_obj    AS int) AS loan_obj_n
        , TRY_CAST(n.f_inv       AS int) AS f_inv_n
        , CASE WHEN a.bin IS NOT NULL THEN 1 ELSE 0 END AS in_b2a
    FROM       [CL_PORTFOLIO].[dbo].[AQR2026_B1A_2025_Q4]         AS n
    LEFT JOIN  [personal_tables].[dbo].[RA_NST_B2A_AQR2026] AS a
           ON  a.bin = n.iin_bin
    WHERE n.is_del = '0'
),
b1a_agg AS (
    SELECT *, SUM(zadol) OVER (PARTITION BY iin_bin) AS zadol_borrower FROM b1a
)
SELECT *
    , CASE WHEN stage_b = '4'             THEN '3'
           WHEN stage_b = '1111111111111' THEN '1'
           ELSE stage_b END AS stage

    -- продуктовый сегмент: единственное значение сегмента (Р1, Р2)
    , CASE
        WHEN COALESCE(debtor_type_n,0) = 0 AND COALESCE(debtor_se_n,0) = 0
          THEN CASE loan_obj_n WHEN 1 THEN 'RETEST'   -- жилая недвижимость
                               WHEN 6 THEN 'RETCAR'   -- автотранспорт
                               ELSE        'RETCON' END
        WHEN loan_obj_n IN (1,2,3)  THEN 'COREST'     -- недвижимость выше размера
        WHEN ent_type_n = 1         THEN 'CORLAR'     -- Р3: ошибка 25-43 %
        WHEN ent_type_n = 2         THEN 'CORMED'
        WHEN ent_type_n = 3         THEN 'RETSML'
        ELSE 'X'
      END AS segment_afr

    -- флаги: сосуществуют с сегментом, не заменяют его (Таблица 3)
    , CASE WHEN entity = 'EUB1'          THEN 1 ELSE 0 END AS flag_disass
    , CASE WHEN lsboo  = 1               THEN 1 ELSE 0 END AS flag_relate
    , CASE WHEN COALESCE(f_inv_n,0) = 1  THEN 1 ELSE 0 END AS flag_corinv
    , CASE WHEN in_b2a = 1
             OR zadol_borrower > @capital * @thr_ind THEN 1 ELSE 0 END AS flag_individual
    , CASE WHEN in_b2a = 1                           THEN 'B2A'
           WHEN zadol_borrower > @capital * @thr_ind THEN 'threshold'
           ELSE NULL END                                   AS individual_basis
    -- признак для ЧПД: сегмент Таблицы 5 «Крупные займы ФЛ (более 200 млн)»
    , CASE WHEN COALESCE(debtor_type_n,0) = 0 AND ead_n > 200000000
           THEN 1 ELSE 0 END                               AS flag_retail_over_200m
FROM b1a_agg
OPTION (MAXDOP 1);
```
