# Восстановление правил сегментации по эталону регулятора

`segment_rules_colab.ipynb` — для Google Colab, `segment_rules_colab.py` — тот же код
ячейками `# %%` для локального запуска. Файлы синхронны: `.ipynb` собирается из `.py`.

## Зачем

Регулятор прислал финальное распределение по сегментам — то, которое он считает
правильным. Скрипт по нему восстанавливает **правила**: какие колонки реально
участвуют в решении, с какими порогами, и какого минимального набора полей
достаточно, чтобы воспроизвести распределение самим.

## Что нужно на входе

Одна таблица (`csv` или `xlsx`), где к строкам нашей отчётности добавлена колонка
с финальным сегментом регулятора. Если рядом положить и нашу `segment_afr` —
дополнительно посчитается матрица расхождений.

Правится одна ячейка — `CONFIG`: путь к файлу, имя колонки регулятора, величина
собственного капитала и отчётная дата.

## Что получается на выходе

| Файл | Содержание |
|---|---|
| `pravila_segmentacii.txt` | правила по каждому сегменту в виде «ЕСЛИ … ТО …» плюс полное дерево |
| `znachimye_kolonki.csv` | колонки, ранжированные по вкладу в решение |
| `spravochnik_znacheniy.csv` | по каждой значимой колонке — все значения, частоты и в какие сегменты они ведут |
| `rashozhdeniya.csv` | пары «наш сегмент → сегмент регулятора» с числом договоров |

`spravochnik_znacheniy.csv` — это и есть то, что запрашивается у смежников:
перечень фактических значений с расшифровкой (`SEGMENT_KEY_COLUMNS.md`, раздел 2).

## Три признака, которые считаются заранее

Дерево работает построчно и само их не найдёт, поэтому они собираются до обучения:

| Признак | Зачем |
|---|---|
| `eng_zadol_borrower`, `eng_share_capital`, `eng_over_02pct` | критерий индивидуальных займов — «**общая** задолженность превышает 0,2 % капитала», то есть агрегат по заёмщику |
| `eng_srok_let`, `eng_srok_ge_5let` | критерий инвестиционных займов — срок 5 и более лет |
| `eng_zadol_metod`, `eng_zadol_script` | две базы задолженности: по определению методики (без пеней) и как считает наш скрипт (с пенями) — видно, какую использует регулятор |

Без них сегменты `Individual loans` и `CORINV` не восстанавливаются в принципе.

## Проверка на синтетике

Скрипт прогнан на сгенерированной выгрузке той же структуры (40 000 строк,
11 сегментов), где правила распределения были заданы заранее — десять колонок
с известными порогами.

Результат: восстановлены **все десять** колонок, включая порог `0,2 %`
(найдено `eng_share_capital > 0.00200061`) и критерий срока
(`eng_srok_ge_5let > 0.5`). Лишние колонки отброшены с нулевым приростом.
Точность на контрольной выборке 0,9981, macro-F1 0,97.

Глубина дерева по умолчанию — 12. На 8 качество заметно хуже (macro-F1 0,88),
потому что правила вложенные; на 16 прироста уже нет.

## Оговорки

**ПДн.** Выгрузка содержит `iin_bin`, `name`, `contract_number`, `account_no`.
`iin_bin` нужен для агрегата по заёмщику и удаляется сразу после его расчёта,
остальные — на том же шаге. Но исходный файл всё равно загружается целиком,
поэтому Colab — внешний сервис — для боевых данных не годится: тот же `.py`
запускается локально без единой правки.

**Дерево показывает корреляцию, а не норму.** Восстановленное правило может
совпадать с критерием методики случайно — особенно на редких сегментах.
Любое правило из вывода сверяется с `GROUND_TRUTH_SEGMENTS.md` прежде,
чем попасть в скрипт.

**Сегменты меньше 30 строк** пропускаются: правило по ним неотличимо
от подгонки. В выводе они помечены явно.

**Охват правил может превышать размер сегмента.** Веса классов выровнены
(`class_weight="balanced"`), поэтому лист засчитывается сегменту и при неполном
большинстве. Смотреть надо на чистоту, а не на число строк в листе.
