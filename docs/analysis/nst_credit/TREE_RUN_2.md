## 1. Сначала — ошибка в моём коде, из-за которой часть правил показана неверно

В выводе стоит:

```
### COREST — в сегменте 52 строк
1) ЕСЛИ ent_type == '3' И eng_srok_let > 3.25 И ... ТО COREST (строк 753, чистота 99.9%)
```

**Это невозможно.** Сегмент из 52 строк не может быть покрыт правилом на 753 строки
с чистотой 99,9 %. Причина — в том, как я считал чистоту.

`DecisionTreeClassifier` обучался с `class_weight="balanced"`, а `tree_.value`
хранит **взвешенные** доли. Для `COREST` вес выходит 1 754 против 0,147
у `RETCON` — отношение почти **12 000 : 1**. Лист, где 5 строк из 753 относятся
к `COREST`, показывает «чистоту 98,8 %» вместо настоящих **0,7 %**.

Затронуты все правила по малым сегментам и весь блок расхождений:

| Что показано | Размер сегмента | Правило заявляло |
|---|---|---|
| `COREST` | 52 | 753 строки |
| `CORMED` | 1 229 | 3 728 строк |
| `CORLAR` | 601 | 2 202 строки |
| `RETSML` | 2 152 | 3 117 строк |

**Не затронуты** правила по крупным сегментам — `RETCON`, `RETCAR`, `RETEST`:
там веса близки и искажение пренебрежимо. Именно эти правила ниже и остаются
в силе.

Исправлено: чистота считается по фактическим строкам (`apply()` → раскладка
по листьям → обычные доли), в выводе печатается «строк в листе N, из них
сегмент M». Добавлен порог `min_rule_purity = 0.80` по фактической чистоте.

## 5. Корпоративная сегментация НЕ воспроизводится — и это главный результат

Качество по сегментам на контрольной выборке:

| Сегмент | Точность (precision) | Полнота (recall) | F1 |
|---|---|---|---|
| `RETCON` | 1,0000 | 0,9980 | 0,9990 |
| `RETCAR` | 1,0000 | 0,9977 | 0,9989 |
| `RETEST` | 1,0000 | 0,9952 | 0,9976 |
| `CORLAR` | 0,9172 | 0,9638 | 0,9399 |
| `RETSML` | 0,9310 | 0,8878 | 0,9089 |
| `COREST` | 0,6400 | 0,9412 | 0,7619 |
| **`CORMED`** | **0,3991** | 0,9003 | **0,5531** |

`CORMED` ловится с полнотой 90 %, но **точность 40 %**: на каждый верно
отнесённый договор приходится полтора ошибочных. Это не дефект модели —
это значит, что **из допустимых критериев корпоративный сегмент не выводится**.

Справочник объясняет почему. Наш `ent_type` не согласуется с эталоном:

| `ent_type` | Строк | Куда относит эталон |
|---|---|---|
| `0` (физлицо) | 725 630 | `RETCON` 86 %, `RETCAR` 14 % |
| `3` (малый) | 2 849 | `RETSML` **72 %**, `CORMED` 21 %, `CORLAR` 4 % |
| `2` (средний) | 699 | `CORMED` **57 %**, `CORLAR` 27 %, `RETSML` 15 % |
| `1` (крупный) | 513 | `CORLAR` **58 %**, `CORMED` 41 % |

Для розницы соответствие полное. Для бизнеса — от 57 до 72 %, то есть
**каждый третий-четвёртый договор эталон относит не туда, куда указывает
наш `ent_type`**.

Это сходится с разбором расхождений: 347 из 455 подлинных несовпадений
(76 %) лежат на границе `RETSML` ↔ `CORMED` ↔ `CORLAR`, причём в обе стороны.

**Вывод.** Таблица 4 определяет размер бизнеса по численности работников
и годовому доходу (ст. 24 Предпринимательского кодекса). Этих полей в выгрузке
нет — есть только производный `ent_type` из РСП. Эталон, по-видимому, опирается
на другой снимок РСП либо на прямые критерии. **Без этих данных корпоративная
часть сегментации не воспроизводится ни деревом, ни правилами.** Это предмет
запроса, а не моделирования.

## 7. Универсальный набор правил — что можно взять уже сейчас

Розничная часть выводится, воспроизводится и опирается только на справочник АФР:

```sql
-- Розница: физлицо, не ИП
WHEN debtor_type = '0' AND debtor_se = '0' THEN
     CASE loan_obj
       WHEN '1' THEN 'RETEST'    -- жилая недвижимость
       WHEN '6' THEN 'RETCAR'    -- автомобильный транспорт
       ELSE        'RETCON'      -- потребительские и прочие
     END
-- Недвижимость
WHEN loan_obj IN ('1','2','3') THEN 'COREST'
-- Размер бизнеса — ПОКА по ent_type, но соответствие лишь 57-72 %
WHEN ent_type = '1' THEN 'CORLAR'
WHEN ent_type = '2' THEN 'CORMED'
WHEN ent_type = '3' THEN 'RETSML'
```

Признаки `DISASS`, `RELATE`, `Individual loans` при этом **не являются
значениями сегмента** — они выносятся в отдельные колонки-флаги, а сам заём
классифицируется по продуктовым критериям. Именно так делает эталон,
и именно этого требует Таблица 3.

Что в этом наборе **нельзя** переносить на следующий год без пересмотра:
границы размера бизнеса. Они и сейчас неверны на четверть корпоративных
договоров.
