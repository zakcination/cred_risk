# Допущения и ограничения НСТ

Разделены на три группы: **задано регулятором** (не обсуждается), **выбрано банком**
(наше решение, требует обоснования в пояснительной записке) и **требует решения**
(открыто). Обновлено 20.08.2026.

---

## 1. Задано регулятором

| № | Допущение | Источник |
|---|---|---|
| Р1 | **Из стадии 3 нет возврата.** «В рамках НСТ недопустимы переходы из стадии 3 в стадии 1 и 2»; TR³⁻³ = 1. Задолженность стадии 3 накапливается: итог = существующая на старте + накопленные переходы | п. 49, 79 |
| Р2 | **Провизии по стадии 3 фиксируются.** «После перехода в стадию 3 сформированные провизии фиксируются до конца горизонта НСТ. Прирост провизий по стадии 3 в каждом квартале возникает в результате новых переходов» | п. 68 |
| Р3 | **Стартовая точка — результаты AQR.** Метрики на отчётную дату берутся из AQR, квартальные вероятности переходов корректируются на его результаты | п. 76 |
| Р4 | **Метрики point-in-time**, то есть чувствительные к макропараметрам сценария | п. 60 |
| Р5 | **Совершенное предвидение при расчёте LRLT**: «последующие изменения макропараметров известны на момент расчёта провизий и полностью соответствуют сценарию» | п. 53, 54 |
| Р6 | **Низкий кредитный риск**: годовая PD < 0,3 % (квартальная вероятность перехода в стадию 3 < 0,075 %) | п. 44 |
| Р7 | **Залог ограничен сверху размером задолженности** и учитывается с дисконтами; при отсутствии внутренних дисконтов применяются регуляторные коэффициенты ликвидности | п. 50 |
| Р8 | **Горизонт 12 кварталов**, сценарии базовый и стрессовый, мгновенные шоки берутся как наихудшее квартальное значение макропараметра | п. 1.2, 1.3.1 |
| Р9 | **При отсутствии внутренней модели** допускается аппроксимация по историческим наблюдениям, но «только такие корректировки, которые ведут к более консервативной оценке» | п. 77 |

**Важное следствие Р1 — уточнено 21.08.2026.** Первоначально я записал это допущение
как прямое противоречие нашему cure-анализу стадии 3 (контур `sql/stage3_*`).
Инструкция к шаблону показывает, что противоречия нет: запрет касается **матрицы
переходов**, но в шаблоне есть отдельные поля «уровень выхода из дефолта… (cure
rate¹⁻³)» и «(cure rate²⁻³)» с оговоркой — «Если банки не могут в явном виде
вычислить данный показатель из своих моделей, они могут не указывать их в шаблоне;
**тем не менее, банки учитывают их при расчёте доли потерь при дефолте (LGD)**».

То есть восстановление в НСТ учитывается **внутри LGD**, а не как переход между
стадиями. Наш cure-анализ — прямой источник для этих полей, а не конкурирующая
методология. Утверждение «НСТ систематически консервативнее внутренней модели
на величину cure» отзывается: оно верно только в части динамики стадии 3,
но не в части уровня потерь.

## 2. Выбрано банком (наши решения, требуют обоснования)

| № | Допущение | Где реализовано | Риск |
|---|---|---|---|
| Б1 | `stage_b = 4` приравнивается к стадии 3 | скрипт сегментации и расчёта | Нужно зафиксировать, что означает код 4 в источнике |
| Б2 | `stage_b = '1111111111111'` (заглушка) приравнивается к стадии 1 | там же | Заглушка трактуется как «нет обесценения» — при массовом появлении занижает риск |
| Б3 | Заглушки метрик `1111111111111` / `9999999999999` заменяются на 0 | там же | **Занижает средневзвешенные**: значение обнуляется, а вес в знаменателе остаётся. См. `SQL_REVIEW.md`, замечание 1 |
| Б4 | Порог индивидуальной значимости — 0,2 % капитала, число зашито на 01.01.2025 | шаг 5 сегментации | При смене отчётной даты порог не обновляется автоматически |
| Б5 | Средневзвешивание CCF по внебалансу, LGD и PD — по EAD | расчёт `*_sred` | **Неверно для LGD.** Инструкция требует вес EAD **× вероятность перехода из стадии**; наш вес — только EAD. См. `GLOSSARY.md`, раздел 4 и `SQL_REVIEW.md`, замечание 12 |
| Б6 | Штрафы (`penalty`) включены в задолженность | расчёт `summa_zadol` для B1A | **Основания не найдено ни в одном из двух текстов.** Определение задолженности (п. 44 руководства и Таблица 2 Инструкции) — «основной долг, дисконты/премии, начисленное вознаграждение»; расчёт возврата «не учитывает пени / штрафы». Требуется решение об исключении |
| Б7 | Для пяти корпоративных портфелей в AQR-2025 использована **одна общая матрица миграций** (1→1 = 0,969; 2→2 = 0,7702) | результаты AQR | Объединение оправдано малым числом наблюдений, но должно быть заявлено явно |
| Б8 | LGD = 0,695 повторяется у четырёх корпоративных портфелей | результаты AQR | Похоже на значение по умолчанию; требуется указать источник |

## 3. Требует решения

| № | Вопрос | Почему важно |
|---|---|---|
| О1 | Как перераспределить «Индивидуальные займы» и «ОУСА» по продуктовым портфелям для кредитного риска | Требование Таблицы 3; сейчас не реализовано. Индивидуальные займы — крупнейший портфель (501 млрд ₸) |
| О2 | Как пересчитать годовую `pd_c12` в квартальные TR¹⁻³ и TR²⁻³ | **Сужен.** Инструкция: за год TR¹⁻³ = PD 12m стадии 1, TR²⁻³ = PD 12m стадии 2 — годовой лист заполняется напрямую. Открытым остаётся только способ перехода к квартальным значениям; регулятор его не задаёт |
| О3 | Какой знаменатель покрытия провизиями используем | НСТ считает к EAD (п. 61), лимит 98-3 и № 119 — к задолженности. Значения не совпадут |
| О4 | Периметр файла сегментации: почему только семь кодов из двенадцати | Иначе метрики считаются не по тому периметру |
| О5 | Контроль `X` и `NULL` в сегментации | Сейчас несопоставленные строки исчезают молча |
| О6 | Актуальность ссылок: руководство НСТ-2025 ссылается на № 170 и № 269 | С 2026 года действуют № 85 и № 61 |
| О7 | Класс модели для TR и LR | Регулятор не предписывает; если выбираем регрессию на макрофакторах — обосновать стационарность и устойчивость |
| О8 | Соответствие «портфель НСТ ↔ сегмент банка по МСФО 9» | Лист «КР фактические данные банка» требует матрицы переходов во **внутреннем** разрезе. Заготовка — колонка «Сегмент БАНК» в выгрузке AQR-2025; нужно подтвердить, что это та же сегментация, по которой считаются провизии |
| О9 | Веса LGD: EAD или EAD × вероятность перехода | Инструкция требует двойного взвешивания. Правка меняет значения по всем сегментам и стадиям — до её внесения цифры несопоставимы с шаблоном |
| О10 | Кто заполняет лист «КР расчет RWA» | Приложения 5, 5-1, 6 Постановления № 170 — не наш расчёт провизий, но тот же блок шаблона. Владелец не назначен |

## 4. Об «эффекте улучшения портфеля»

Отдельная оговорка регулятора (п. 62): если банк считает метрики через матрицы
миграций и внутренние рейтинги, в них может учитываться эффект улучшения портфеля —
худшие по качеству активы быстрее уходят в стадию 3, и оставшаяся часть портфеля
становится лучше. «Банки, у которых улучшение портфеля влияет на прогнозируемые
параметры кредитного риска, могут столкнуться с требованием со стороны Агентства
предоставить данные по задолженности и вероятности дефолта на уровне рейтинга».

Практически: если в модели TR зависит от структуры портфеля по рейтингам, нужно быть
готовыми выгрузить разрез по рейтингам. Это стыкуется с мастер-шкалой из контура
`risk_appetite` (Приложение № 4 к Политике, полосы 1–13 / 14–33 / 34–50).
