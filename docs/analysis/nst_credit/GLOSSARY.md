# Словарь метрик НСТ: об одном ли мы говорим

Первый шаг синхронизации: **определения** (говорим ли об одном и том же) и
**понимание** (одинаково ли считаем). Формулировки регулятора приведены дословно
по двум документам АРРФР: **Методологическое руководство НСТ-2025** (ссылки — на
параграфы) и **Инструкция к шаблону НСТ для банков, 2025** (ссылки — на пункты
и таблицы, раздел 6 ниже). Обновлено 21.08.2026.

---

## 1. Стадии обесценения

| Термин | Определение регулятора (п. 44) | Как у нас |
|---|---|---|
| Стадия 1 | «отсутствует значительное увеличение кредитного риска… провизии в размере, равном ОКУ за 12 месяцев» | `stage_b = 1` |
| Стадия 2 | «присутствует значительное увеличение кредитного риска… провизии в размере ОКУ за весь срок актива, но не соответствует определению стадии 3» | `stage_b = 2` |
| Стадия 3 | «задолженность по кредитно-обесцененным активам… провизии в размере ОКУ за весь срок жизни актива» | `stage_b = 3`, а также `stage_b = 4 → 3` (наше приведение) |

Задолженность в определении регулятора «включает основной долг, дисконты/премии,
начисленное вознаграждение» (п. 44). В нашем расчёте по B1A:
`od + od_del + interest + interest_del + correction + disc_prem + penalty`.
**Расхождение:** мы добавляем `penalty` (штрафы), регулятор в определении их
не называет. Вопрос к сверке — включать ли штрафы в базу.

**Низкий кредитный риск** (п. 44): актив может быть отнесён к низкому кредитному
риску в отдельный квартал, если «годовая вероятность дефолта на начало этого квартала
менее 0,3 % (квартальная вероятность перехода в стадию 3 менее 0,075 %)».

## 2. Ядро НСТ: TR, LR, LGD

Определения из п. 60. **Надстрочный индекс означает переход между стадиями
в данном квартале.**

| Метрика | Расшифровка | Определение | Период |
|---|---|---|---|
| **TR** | transition rate | «вероятность перехода между стадиями в течение квартала» | квартал |
| TR¹⁻² | | переход из стадии 1 в стадию 2 за квартал | квартал |
| TR²⁻¹ | | переход из стадии 2 в стадию 1 за квартал | квартал |
| **TR¹⁻³** | | «вероятность перехода задолженности, которая на начало квартала находилась в стадии 1, в стадию 3 в течение квартала **(вероятность дефолта в течение квартала — PD¹⁻³)**» | квартал |
| **TR²⁻³** | | то же из стадии 2 (PD²⁻³) | квартал |
| TR¹⁻¹ | | «рассчитывается как 1 − TR¹⁻² − TR¹⁻³» | квартал |
| TR²⁻² | | «рассчитывается как 1 − TR²⁻¹ − TR²⁻³» | квартал |
| TR³⁻³ | | равна 1: переходы из стадии 3 запрещены (п. 79) | квартал |
| **LR** | loss rate | ожидаемый уровень потерь | — |
| LR12m | loss rate 12 months | «ожидаемый уровень потерь на горизонте 12 месяцев» — для стадии 1 (п. 79) | 12 мес. |
| LRLT | loss rate lifetime | «ожидаемый уровень потерь на всём сроке жизни актива» — для стадий 2 и 3 (п. 79) | срок актива |
| LRLT¹⁻² | | уровень потерь за срок актива по задолженности, перешедшей из 1 в 2; «рассчитывается исходя из PD lifetime и соответствующей LGD²⁻³» (п. 60) | срок актива |
| LRLT²⁻² | | то же по оставшейся в стадии 2 | срок актива |
| LRLT³⁻³ | | «поскольку задолженность в стадии 3 уже находится в дефолте, показатель равен доле потерь в случае дефолта (LGD³⁻³)» | срок актива |
| **LGD** | loss given default | «ожидаемая доля потерь в случае перехода задолженности в стадию 3» | — |
| LGD¹⁻³, LGD²⁻³ | | доля потерь по задолженности, перешедшей в стадию 3 из стадии 1 / 2 за квартал | квартал |

> **Ключевое для синхронизации.** В НСТ «PD» — это не отдельная метрика, а частный
> случай TR: PD¹⁻³ = TR¹⁻³ и PD²⁻³ = TR²⁻³, обе **квартальные**. Наши поля из AQR
> `pd_c12` (PD 12 месяцев) и `pd_cl` (PD lifetime) — это **годовые и пожизненные**
> величины, а не квартальные вероятности перехода. Прямое равенство
> `pd_c12 = квартальный TR¹⁻³` **неверно**.
>
> **Инструкция к шаблону снимает неоднозначность** и задаёт соответствие явно:
> — в **годовом** разрезе (лист «КР фактические данные банка»): TR¹⁻³ за год
> «равнозначно фактической вероятности дефолта на горизонте 12 месяцев (PD 12m)
> для задолженности в стадии 1», TR²⁻³ за год — «равнозначно фактической PD 12m
> для задолженности в стадии 2»;
> — в **квартальном** разрезе PD 12m «используется для моделирования 12-месячных
> ожидаемых кредитных потерь, **а также для определения квартальной вероятности
> перехода из стадии 1 в стадию 3**».
>
> То есть годовая матрица переходов заполняется нашей `pd_c12` напрямую,
> а квартальная TR¹⁻³ из неё **выводится** — способ пересчёта регулятор
> не предписывает, это наше методологическое решение (см. `ASSUMPTIONS.md`, О2).

## 3. Объёмные метрики

| Метрика | Определение регулятора | Наше поле |
|---|---|---|
| **EAD** | «объём требований, подверженных риску дефолта… рассчитывается как сумма задолженности и внебалансовых активов, умноженных на коэффициент конверсии (CCF)» (п. 45) | `ead` в B1A/B1B |
| **CCF** | коэффициент конверсии внебалансовых обязательств (п. 45, 79) | `ccf` |
| Задолженность без признаков обесценения | «задолженность в стадии 1 и стадии 2» (п. 46) | стадии 1 + 2 |
| Объём перехода к стадии 3 | «сумма задолженности в стадии 3 на конец квартала, которая на начало квартала была в стадии 1 или стадии 2» (п. 49) | считается по паре срезов |
| Уровень покрытия провизиями | «отношение величины провизий по определённой стадии к задолженности под риском (EAD) соответствующей стадии» (п. 61) | `provisions / ead` |
| Залоговое обеспечение | «все залоги, доступные для обеспечения задолженности», с дисконтами и **ограничением сверху размером задолженности** (п. 50) | из шаблонов B2 |

**Внимание к знаменателю покрытия.** Регулятор определяет покрытие как
провизии / **EAD** (п. 61). В лимите 98-3 главы 11 Нормативов № 85 и в постановлении
№ 119 покрытие считается как провизии / **задолженность стадии 3 + ПСКО** (без CCF
и внебаланса). Это **разные знаменатели** — значения не совпадут. При переносе цифр
между НСТ и отчётностью по лимитам обязательно указывать, какой знаменатель.

## 4. Как считаем: наши поля и их обработка

Из действующего скрипта расчёта (`RA_NST_*`):

| Поле | Смысл | Обработка сейчас |
|---|---|---|
| `stage_b` | стадия по балансу | `4 → 3`, `1111111111111 → 1` |
| `ccf`, `lgd`, `pd_c12`, `pd_cl`, `pd_ol` | риск-метрики займа | заглушки `1111111111111` и `9999999999999` → **0** |
| `ead`, `offbal`, `provisions` | объёмы | как есть |
| `ccf_sred` | средневзвешенный CCF | `ccf × offbal / offbal_total` по (сегмент, стадия) |
| `lgd_sred`, `pd_c12_sred`, `pd_cl_sred` | средневзвешенные | `метрика × ead / ead_total` по (сегмент, стадия) |

Замечания к обработке — в `SQL_REVIEW.md`; главное: **обнуление заглушек занижает
средневзвешенные**, поскольку вес такого займа остаётся в знаменателе.

> **Расхождение по весам LGD.** Мы считаем `lgd_sred = lgd × ead / ead_total` —
> взвешивание **только по EAD**. Инструкция требует иного: LGD — «средневзвешенное
> по сумме задолженности под риском (EAD) **и вероятности перехода из стадии**»
> (Таблица 2), а для стресс-теста дословно: «средневзвешенное по сумме задолженности
> под риском (EAD) **и вероятности перехода из стадии 1 в стадию 3 в течение
> квартала**» (LGD¹⁻³) и то же для LGD²⁻³. Вес — произведение EAD × вероятность
> перехода, а не EAD. Экономический смысл: LGD усредняется по той части портфеля,
> которая **фактически уйдёт в дефолт**, а не по всему портфелю. Правка нужна
> и в расчёте, и в `ASSUMPTIONS.md` (Б5).

Отдельно про заполнение нулями. П. 20 Инструкции: «Если после внесения всех данных,
в шаблоне остаются незаполненные ячейки, банкам необходимо заполнить ячейки нулями».
Это требование к **ячейке шаблона**, а не к обработке заглушек на уровне займа.
Обнулять метрику отдельного займа до взвешивания — не то же самое, что поставить
ноль в незаполненную ячейку портфеля; первое искажает средневзвешенную, второе нет.

## 5. Что регулятор НЕ требует

Проверено поиском по тексту Методологического руководства:

- слова **«стационарность» и «регрессия» не встречаются ни разу**;
- п. 79: банки моделируют риск-метрики **«используя собственные модели»**;
- требование к метрикам одно (п. 60): они должны быть **point-in-time**, то есть
  «учитывать изменения макропараметров в результате применения сценариев НСТ».

**Следствие.** Регрессия временных рядов на макрофакторах — это наш выбор способа,
а не предписание. Приведение рядов к стационарности — требование эконометрики
(иначе регрессия даёт ложную связь), а не регулятора. В пояснительной записке
достаточно описать методологию (п. 78), но выбор класса модели за банком.

## 6. Что требует шаблон: состав полей блока «Кредитный риск»

Источник — «Надзорное стресс-тестирование банков второго уровня. Инструкция
к шаблону НСТ для банков», АРРФР, 2025. Блок кредитного риска — четыре листа
(п. 17):

| Лист | Кто заполняет | Что именно |
|---|---|---|
| **КР обзор провизий** | автоматически | агрегаты по всем портфелям, балансовые показатели после валютного риска |
| **КР расчет провизий** | банк | риск-метрики на отчётную дату и в стресс-тесте, поквартально, в разрезе портфелей и стадий |
| **КР фактические данные банка** | банк | фактические матрицы переходов **за квартал и за год** по внутренней сегментации |
| **КР расчет RWA** | банк | объёмы активов / условных и возможных обязательств и RWA по приложениям 5, 5-1, 6 Постановления № 170 |

Общие требования: объёмы — **в тысячах тенге** (п. 19); валютные активы —
по курсу на отчётную дату; незаполненные ячейки после внесения всех данных
заполняются нулями (п. 20).

### 6.1. Отчётная дата (Таблица 2) — что мы обязаны дать

| Поле | Стадия | Наше соответствие |
|---|---|---|
| PD 12m | 1 | `pd_c12` по стадии 1 |
| TR¹⁻² за квартал | — | **нет**, требуется расчёт по парам срезов |
| TR¹⁻³ за квартал | — | выводится из PD 12m |
| PD lifetime | 2 | `pd_cl` по стадии 2 |
| TR²⁻¹ за квартал | — | **нет**, требуется расчёт |
| LGD | 1, 2, 3 | `lgd`, но вес нужно менять (EAD × вероятность перехода) |
| Задолженность до вычета провизий | 1, 2, 3 | `summa_zadol` |
| Внебалансовые активы | 1, 2, 3 | `offbal` |
| CCF | 1, 2, 3 | `ccf` |
| Стоимость залогового обеспечения | 1, 2, 3 | шаблоны B2 |
| Средневзвешенный оставшийся срок погашения | **только 2** | `srok`, единицы измерения проверить |
| Провизии | 1, 2, 3 | `provisions` |

> **TR²⁻³ на отчётную дату в Таблице 2 не запрашивается** — только в стресс-тесте
> (Таблица 3) и в годовом/квартальном разрезе фактических данных. Это не описка:
> для стадии 2 на отчётную дату регулятор берёт PD lifetime.

Уточнения по формату, которые легко пропустить:

- **Срок для стадии 2** — «взвешенное по объёму задолженности количество **лет**
  до погашения займов 2 стадии. **Округляется до десятых долей года**». В выгрузке
  результатов AQR-2025 колонка называется «Оставшийся срок погашения (для займов
  в стадии 2)», единица измерения в шапке — **«Месяцы»**; заполнена только
  по стадии 2 (по стадиям 1 и 3 нули). Пример: «Займы ЛСБОО», стадия 2 — 9,6748.
  **Это месяцы, а шаблон ждёт годы**: 9,6748 мес. = 0,8 года. Перенос значения
  как есть завысил бы срок в 12 раз. Пересчёт обязателен и должен быть
  зафиксирован в пояснительной записке.
- **Залог**: аллоцированная стоимость на момент последней оценки, с дисконтами
  банка, подтверждёнными статистикой; при отсутствии внутренних моделей —
  коэффициенты ликвидности Постановления Правления НБК **№ 269** (в Инструкции
  редакции 2025 года; с 2026 года действует № 61 — см. `ASSUMPTIONS.md`, О6).
  Ограничение сверху — **EAD, на уровне займа**, а не на уровне портфеля.
- **LGD выводится из уровня возврата**: «банки рассчитывают уровень возврата
  (recovery rate), который возвращается в виде денег (recovery cash) и в виде
  залогового имущества (recovery collateral). Расчёт возврата в виде денег
  **не учитывает пени / штрафы** и возвраты в виде залогового обеспечения».
  То есть штрафы исключены из возврата явно; в определении задолженности
  («основной долг, дисконты/премии, начисленное вознаграждение») их тоже нет.
  Наше включение `penalty` в `summa_zadol` не опирается ни на один из двух текстов.

### 6.2. Cure rate: он есть в шаблоне

Отдельные поля стресс-теста: «Уровень выхода из дефолта задолженности в течение
всего срока жизни актива, перешедшей из стадии 1 в стадию 3 в течение квартала
(cure rate¹⁻³)» и то же для cure rate²⁻³. Формулировка: «Если банки не могут
в явном виде вычислить данный показатель из своих моделей, они могут не указывать
их в шаблоне; **тем не менее, банки учитывают их при расчёте доли потерь
при дефолте (LGD)**».

> **Это уточняет допущение Р1.** Запрет переходов из стадии 3 (п. 49, 79) —
> ограничение **матрицы переходов**, а не отрицание восстановления как явления.
> Восстановление в НСТ живёт **внутри LGD**. Наш cure-анализ стадии 3
> (контур `sql/stage3_*`) поэтому не противоречит НСТ, а является прямым
> источником для этих двух полей.

### 6.3. Лист «КР фактические данные банка» — две сегментации сразу

Заполняется «в соответствии с сегментацией банка (для целей МСФО 9) на отчётную
дату НСТ» (п. 34): в одной строке — портфель НСТ **из выпадающего списка**
и «Сегмент Банка» — название по **внутренней** сегментации. Полная матрица
переходов, дважды:

- **за квартал**: TR¹⁻¹, TR¹⁻², TR¹⁻³, TR²⁻¹, TR²⁻², TR²⁻³;
- **за год**: те же шесть, где TR¹⁻³ = фактическая PD 12m стадии 1,
  TR²⁻³ = фактическая PD 12m стадии 2.

> **Следствие для нас.** Нужна не одна карта сегментов, а **две** и связь между
> ними: AQR/НСТ-портфель ↔ внутренний сегмент МСФО 9. Сейчас в скрипте есть
> только первая (`SEGMENTS.md`). Вторая — предмет отдельной сверки с методологами
> провизий, потому что матрицы переходов регулятор ждёт именно во внутреннем
> разрезе.
>
> Заготовка есть: в листе «Детальные результаты — провизии» выгрузки AQR-2025
> присутствует колонка **«Сегмент БАНК»** рядом с портфелем. Начать нужно с неё —
> проверить, совпадает ли она с сегментацией, по которой методологи считают
> провизии по МСФО 9, или является отдельным разрезом.

### 6.4. RWA — смежная зона

Лист «КР расчет RWA» опирается на приложения 5, 5-1 и 6 Постановления Правления
НБК **№ 170**; для «прочих статей» RWA считается неизменным на всём горизонте НСТ
и указывается только на отчётную дату (п. 35). Это не наш расчёт провизий,
но заполняется в том же блоке — владельца поля нужно назначить явно.

## Открытые вопросы к сверке

| № | Вопрос | Состояние |
|---|---|---|
| 1 | Включаются ли штрафы (`penalty`) в задолженность | **Практически закрыт против нас.** Ни определение задолженности (п. 44 и Таблица 2 Инструкции), ни расчёт возврата штрафы не включают. Требуется решение: убрать `penalty` из `summa_zadol` |
| 2 | Пересчёт годовой `pd_c12` в квартальные TR | **Закрыт частично.** Годовой разрез: TR¹⁻³ = PD 12m напрямую. Квартальный: PD 12m «используется для определения» квартальной TR¹⁻³ — способ пересчёта за банком, обосновать в пояснительной записке |
