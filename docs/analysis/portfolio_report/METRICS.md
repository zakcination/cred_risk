# Справочник метрик отчёта по портфелю

Заведён 23.09.2026. Русские наименования — редакция автора от 23.09.2026, она здесь
**нормативная**: ниже по репозиторию метрика называется так и только так.

Нумерация сохранена корейская (`2-1 ①`, `4-1 ④`) намеренно. Она — единственная
ссылка на отраслевой образец, по которой можно проверить, что мы не потеряли
раздел и не склеили два в один. Своя сквозная нумерация это свойство убила бы.

## Как читать вердикт

| Вердикт | Что означает |
|---|---|
| **считается** | поле проверено живым аудитом, формула выписана, ограничений нет |
| **выбор автора** | считается, но кандидатов на поле больше одного. По §6 выбор принадлежит автору, не Клоду. Чем разрешается — указано |
| **не считается** | данных нет в витрине. В последней колонке — что именно надо запросить |

Вердикт «считается» не ставится по заполненности. `days_past_due_principal` по S02
заполнен на 100 % и везде равен нулю — это и есть образец заполненности без содержания.

## 2-1 신규 취급 현황 — Новые выдачи

Единица наблюдения — **договор**, попавший в месяц по `l_funding_date`.
Поле заполнено на 100 % по всем четырём источникам — это установлено аудитом
и является причиной, по которой слой «поток» вообще строится без истории срезов.

| № | 한국어 | Наименование | Определение | Вердикт |
|---|---|---|---|---|
| ① | 취급액 | **Объём выдач** | сумма выданного за месяц | **считается** — `l_loan_amount` (RPT_D 24.09.2026: `l_limit` пуст на 100 % по S01, S03, S17). **Кроме S02:** там `l_loan_amount` совпадает с `l_limit` в 99,9 % строк и нулевой в 79,6 % — это лимит, а не выдача. По картам объём идёт отдельной колонкой «установлено лимитов» и в ① не суммируется |
| ② | 취급건수 | **Количество выдач** | `COUNT(l_gid)` за месяц | **считается** |
|  |  | **в т.ч. карт с лимитом** | S02: карты с `l_loan_amount` > 0 среди выданных | **считается** — К-1, вариант Б (решение автора 24.09.2026). 71–99 % выданных карт S02 — без лимита, остаток был у 1,6 % из них (`RPT_H`); без этой строки «Количество выдач» у Карт читается как выдача кредитных карт. Лимит — на снимке 01.09.2026: у закрытых карт обнулён (Р-8) |
| ③ | 건당취급액 | **Средняя сумма выдачи** | ① / ② | **считается** после ① |
| ④ | 약정 대출기간 | **Срок по договору** | срок, записанный в договоре при выдаче | **считается** — `l_initial_term_months`, по определению «при выдаче»; `l_current_term_months` — другая метрика (срок после изменений). Заполнен на 100 % по S01, S03, S17. По S02 пуст — у карт срока нет по природе продукта. Нулевые сроки (минимум 0 на S01 и S03) — аномалия, в среднем не участвуют |
| ⑤ | 실대출기간 | **Фактический срок** | `DATEDIFF(month, l_funding_date, l_actual_closure_date)` по закрытым | **считается** |

Ловушка ④ и ⑤ вместе: это **не** одна метрика в двух состояниях. ④ берётся
по выданным в месяц, ⑤ — по закрытым в месяц. Знаменатели разные, и сравнивать
их между собой на одной строке отчёта нельзя — это разные когорты.

## 2-3 완납월 평균만기 — Фактический срок до полного погашения

Единица наблюдения — **договор, закрытый в месяц** (`l_actual_closure_date`
в месяце и класс статуса «закрыт» по `dict_registry/status_map.csv`).

| № | 한국어 | Наименование | Определение | Вердикт |
|---|---|---|---|---|
| ① | 평균만기 | **Средний фактический срок** | среднее от 2-1 ⑤ по когорте месяца | **считается** |
| ② | 완납건수 | **Количество полностью погашенных** | закрытые в месяц, класс «закрыт» | **считается** |
| ③ | 완납건수(중도상환) | **в том числе досрочно** | закрытые раньше плановой даты | **считается** — `l_actual_closure_date < l_scheduled_closure_date`, только внутри класса «закрыт». Проверено на эталоне, см. ниже |

**Как установлено правило ③ (RPT_D, 24.09.2026).** Прямой признак досрочного
погашения есть только у S03: статус `Z` = *Closed TAR / закрыт досрочно*,
3 164 895 договоров. Он послужил эталоном для трёх кандидатов на плановую дату:

| Кандидат | Срабатывает на `Z` (досрочно) | на `C` (закрыт) | Вердикт |
|---|---|---|---|
| **`l_scheduled_closure_date`** | **99,98 %** (3 164 352) | **3,3 %** (112 191) | **верен** |
| `l_loan_maturity_date` | 3,2 % | 0,04 % | досрочное не отделяет |
| `l_end_date` | 100 % | 100 % | срабатывает на всём подряд — технический конец действия записи в паре с `l_start_date`, не бизнес-дата |

Правило переносится на источники без эталона: S01 — 59 % закрытий досрочные,
S17 — 82 %. По S02 плановой даты нет — у карт досрочного погашения не бывает
по построению.

**Фильтр класса обязателен.** Расторгнутые (`V`), отменённые (`A`) и списанные (`I`)
тоже закрываются раньше плана — на 100 %, 99,4 % и 30,7 %. Без фильтра «закрыт»
в досрочные погашения попали бы **119 545** расторжений, отмен и списаний.

**S17 `Т`** (23 786): закрыт раньше плана в 99,9 % случаев, остатка нет — ведёт
себя как `Z`. Но смысл статуса неизвестен, и отличить досрочное погашение от
переоформления нечем. До расшифровки `Т` в ③ **не входит** и печатается сноской.

## 3 자산 현황 — Портфель

Единица наблюдения — **счёт** (`loan_account` на дату среза), периметр —
действующие договоры по карте статусов. Отбор — в `README.md` контура.

| № | 한국어 | Наименование | Определение | Вердикт |
|---|---|---|---|---|
| ① | 총잔액 | **Общий остаток задолженности** | `SUM(total_balance_debt)` | **считается** |
| ② | 유잔액건수 | **Количество договоров с остатком** | счета с `total_balance_debt <> 0` | **считается** |
| ③ | 유잔액 회원수 | **Количество заёмщиков с остатком** | `COUNT(DISTINCT l_borrower_id)` | **считается в пределах источника** — заполнен на 100 %: S01 26 340 заёмщиков на 38 223 договора, S02 548 396 на 605 639, S03 3 190 953 на 7 099 940, S17 399 251 на 488 115. **Сквозной итог по банку — только через ИИН** из `borrower`: идентификатор заёмщика системный, один человек в двух системах имеет два разных номера. Межисточниковые коллизии (RPT_D блок 4б) не измерены |
| ④ | 인당 잔액 | **Остаток на одного заёмщика** | ① / ③ | **считается** после ③ |

Ловушка ②. По картам (S02) счёт есть только у 11,3 % действующих договоров.
Это не дефект, а природа продукта: договор без использованного лимита остатка
не имеет. Но **«договоров» и «договоров с остатком» — разные метрики, и по S02
они расходятся в 9 раз.** Строка ② обязана быть в отчёте отдельно от ②
раздела 2-1, иначе разрыв читается как потеря данных.

## Две пары, которые сливались

Правка автора от 23.09.2026. Записана отдельно, потому что это не вопрос
благозвучия: в прежней редакции две пары метрик назывались одинаково и
на отчёте складывались в одну строку.

**4-1 ① и ④ — оба назывались «уровень перехода».** Это разные переходы:
из текущей в двухмесячную и из двухмесячной в семимесячную. Второй —
фактически дорога к списанию, и управленческое решение по нему другое:
по первому работает soft collection, по второму — уже нет.

**11 ③ и ⑤ — «уровень одобрения» и «уровень кредитования».** Знаменатели
разные: рассмотрено и одобрено. По названиям это не видно, а перепутать
их — значит объяснять падение выдач ужесточением скоринга там, где на
самом деле клиент ушёл после одобрения.

### Что из этого следует практически

Ни одна из четырёх метрик сегодня не считается. Но **различение превращает
именование в запрос данных** — пока метрика была одна, просить было нечего:

| Метрика | Что запросить | У кого |
|---|---|---|
| 4-1 ① и ④ | просрочка **в месяцах** на каждую дату среза, глубина не менее 7. Не флаг, не корзина, не сумма | владелец витрины |
| 11 ③ и ⑤ | три отдельных счётчика по месяцам: **рассмотрено, одобрено, выдано**. Не «уровень одобрения» одной цифрой | система выдачи |
| 4-1 ⑥ | факт платежа и причитавшуюся сумму по договору за месяц | ядро / система выдачи |
| 2-1 ① | что считается выдачей по возобновляемым (S02) | владелец витрины |

Строка про просрочку в месяцах — прямое следствие этой правки. Если бы
переход остался одной метрикой, глубина 7 в запросе не появилась бы.

## Отозванный кандидат — `l_term`

**Прежняя формулировка** (редакция 23.09.2026): «срок по договору — три кандидата:
`l_term`, `l_initial_term_months`, `l_current_term_months`; `l_term` по S02 пуст
на 100 % (604 137)».

**Опровергнуто прогоном 24.09.2026:** `Invalid column name 'l_term'`. Колонки
с таким именем в `loans` нет. Кандидатов два.

**Причина ошибки, а не просто факт.** Имя было взято из `dict_registry/fields.csv`,
где есть строка `loans;l_term;S02;непригодно;100 % NULL (604 137)`. Реестр — не
живой аудит, и §4 требует брать имена только из `INFORMATION_SCHEMA`. Реестр
воспроизвёл имя с числом при нём, и число придало имени убедительности, которой
у него не было.

**Цена.** Ошибка привязки имени валит батч целиком, поэтому из пяти блоков RPT_D
не отработал ни один — потерян весь прогон, а не один показатель. Поэтому в
RPT_D заведён блок 0 (полный список колонок `loans` из `INFORMATION_SCHEMA`)
и блоки разделены `GO`.

Откуда взялась строка в реестре — выясняет блок 0б: ищет колонку `%term%` по
всей базе. Пусто — строка заведена ошибочно; не пусто — колонка живёт в другом
объекте, и реестр указывает не туда.
