# Сборка отчёта в Power BI — шаг за шагом

Витки 0–2: итог банка → источники → продукты. На каждом шаге есть проверка,
и следующий шаг начинать только после неё: ошибка, пойманная на шаге 2,
стоит минуту, а та же ошибка, найденная на готовой странице, — час.

| Что | Файл |
|---|---|
| данные — три запроса | `PBI_fact_flow.sql`, `PBI_fact_stock.sql`, `PBI_fact_borrowers.sql` |
| весь DAX — вставлять отсюда | `PBI_model.dax` |
| почему модель устроена так | `POWERBI.md` |

**Почему данных три таблицы, а не одна.** У выдач и погашений дата — месяц события,
у остатка — срез на 1-е число. Заёмщики не складываются ни между источниками, ни
между продуктами. Одна широкая таблица смешала бы оба зерна, и итоги строк и
столбцов стали бы молча неверными. Раскладку «как в Excel» делает визуал, а не данные.

---

## Шаг 0. Одна настройка до загрузки

**Файл → Параметры и настройки → Параметры → Текущий файл → Загрузка данных →
снять «Автоматически обнаруживать новые связи после загрузки данных».**

Иначе Power BI сам свяжет `fact_flow` с `fact_stock` по `month_start` и `l_source` —
связью «многие ко многим», которая удвоит цифры, и найти её потом трудно.

---

## Шаг 1. Данные — три запроса

Для каждого файла:

1. Получить данные → SQL Server.
2. Сервер — ваш; база данных — `Dictionaries`; режим — **Импорт**.
3. Дополнительные параметры → Инструкция SQL → вставить файл **целиком**.
4. Загрузить. Переименовать запрос: `fact_flow`, `fact_stock`, `fact_borrowers`.

DirectQuery не подойдёт: запросы используют CTE и `OPTION (MAXDOP 1)`.

**Проверка.** В представлении данных:
- `month_start` — тип «Дата», не «Текст» и не «Дата/время»;
- `product_key` — «Текст»;
- в `fact_flow` 22 столбца, в `fact_stock` — 14, в `fact_borrowers` — 3.

---

## Шаг 2. Справочники и таблица показателей

Моделирование → Новая таблица → вставить из `PBI_model.dax` по очереди:
`dim_source`, `dim_month`, `dim_product`, `Показатель`.

Затем в `dim_month` → Новый столбец → `Последние 12`.

**Таблица для мер** — туда складываются все меры, чтобы не искать их по фактам:

1. Моделирование → Новая таблица (Modeling → New table) → вставить и Enter:
   ```dax
   Меры = ROW ( "служебный", BLANK () )
   ```
2. Панель «Данные» справа → раскрыть `Меры` → правый клик по `служебный` →
   **Скрыть** (в других версиях — «Скрыть в представлении отчета», Hide in report view).

Мера создаётся в той таблице, по которой кликнули: правый клик по **таблице** `Меры`
(не по столбцу) → **Создать меру** → в строке формул заменить `Мера = ` текстом меры.
Попала не туда — выделить меру → Средства меры → Домашняя таблица → `Меры`.

Альтернатива через Главная → Ввести данные: пустая таблица с именем `Меры` → Загрузить;
**после первой меры** правый клик по `Столбец1` → Удалить из модели — таблица станет
таблицей мер (значок калькулятора). Удалять столбец до первой меры нельзя: пропадёт
таблица целиком.

**Проверка.** `dim_month` — 24 строки (09.2024 … 08.2026: поток начинается с 09.2024,
срезы остатка — с 12.2024), `Последние 12 = True` у 09.2025 … 08.2026. `dim_product` — 20 строк, `Показатель` — 20 строк.

## Шаг 3. Сортировка

Для каждой строки таблицы ниже:

1. Панель «Данные» → раскрыть таблицу → **левый клик по имени столбца** (по тексту,
   не по галочке).
2. На ленте появится вкладка **«Средства столбцов»** (Column tools). Нет вкладки —
   выделена таблица, а не столбец.
3. **«Сортировать по столбцу»** (Sort by column) → выбрать столбец из правой колонки.

| Столбец | Сортировать по |
|---|---|
| `dim_source[Источник]` | `Порядок` |
| `dim_month[Месяц]` | `month_idx` |
| `dim_product[Обеспечение]` | `П1` |
| `dim_product[Группа]` | `П2` |
| `dim_product[Продукт]` | `П3` |
| `Показатель[Показатель]` | `Порядок` |

У каждого уровня иерархии свой столбец сортировки: у одного значения уровня должен
быть ровно один номер, иначе Power BI откажет. `dim_month[Месяц]` можно пропустить —
формат `2025-09` и так сортируется верно.

**Проверка** — только на визуале, в панели ничего не меняется: на шаге 6 источники
идут RS → Карты → CrediLogic → Fenix, а не по алфавиту.

---

## Шаг 4. Связи

Представление модели → перетащить поле на поле. Все — «один ко многим»,
направление фильтра — одностороннее, от справочника к факту.

| Справочник | → Факт |
|---|---|
| `dim_month[Date]` | `fact_flow[month_start]`, `fact_stock[month_start]`, `fact_borrowers[month_start]` |
| `dim_source[l_source]` | `fact_flow[l_source]`, `fact_stock[l_source]`, `fact_borrowers[l_source]` |
| `dim_product[product_key]` | `fact_flow[product_key]`, `fact_stock[product_key]` |

`Показатель` и `Меры` ни с чем не связываются.

**Проверка.** Восемь связей, ни одной между двумя фактами, ни одной «многие ко многим».

**Сразу после связей — скрыть ключи в фактах** (правый клик по столбцу → «Скрыть»):
`fact_flow` — `month_start`, `l_source`, `product_key`; `fact_stock` — `month_start`,
`snapshot_date`, `l_source`, `product_key`; `fact_borrowers` — `month_start`, `l_source`.
Иначе рано или поздно фильтр или ось встанет на поле факта вместо справочника, и визуал
опустеет (случилось на сборке 24.09.2026 — фильтр месяца на `fact_flow[month_start]`).
Все показатели — меры, поэтому можно скрыть и числовые столбцы фактов целиком.

---

## Шаг 5. Меры

Выделить таблицу `Меры` → Новая мера → вставить по одной из `PBI_model.dax`.
Двадцать две меры и переключатель `Значение`.

Для `Значение`: Средства меры → Формат → **Динамический** → вставить выражение
из последнего блока `PBI_model.dax`. Без этого все показатели выйдут в одном
формате — штуки с десятыми, доли без процентов.

Скрыть служебную `_Остаток (сумма)`.

## Шаг 6. Контрольные клетки — до любых страниц

Ответ известен из прогонов 24.09.2026. Не сходится — ошибка в связях или в мерах,
и остальным цифрам верить нельзя.

**Матрица 1 — остаток и выдачи.**

1. Слева — «Представление отчета» (верхний значок).
2. «Визуализации» → значок **«Матрица»** (сетка с выделенными первой строкой и столбцом).
3. Не снимая выделения, перетащить из «Данных»:
   Строки ← `dim_source[Источник]`; Столбцы ← `dim_month[Месяц]`;
   Значения ← `Общий остаток, млрд ₸`, `Провизии (1428+1845+18771), млрд ₸`,
   `Покрытие провизиями`, `Количество выдач`.
4. «Фильтры» → «Фильтры для этого визуального элемента» → `Месяц` → оставить
   2025-12, 2026-04, 2026-08 — иначе 24 месяца по 4 колонки.

**Матрица 2 — погашения по продукту.** Клик по пустому месту листа → «Матрица»:
Строки ← `dim_product[Продукт]`; Столбцы ← `Месяц`; Значения ← `Полностью погашено`,
`Закрыто с просрочкой на начало месяца`; фильтр — только 2025-12.

| Матрица | Строка | Месяц | Мера | Ожидается |
|---|---|---|---|---|
| 1 | **Итог** (нижняя) | 2026-08 | Общий остаток, млрд ₸ | **1 521,6** |
| 1 | **Итог** | 2026-08 | Провизии, млрд ₸ | **112,5** |
| 1 | **Итог** | 2026-08 | Покрытие провизиями | **0,074** = 7,4 % |
| 1 | Fenix | 2026-08 | Общий остаток, млрд ₸ | **120,9** |
| 1 | CrediLogic | 2026-04 | Количество выдач | **523** |
| 2 | POS — Fenix | 2025-12 | Полностью погашено | **4 874** |
| 2 | POS — Fenix | 2025-12 | Закрыто с просрочкой на начало месяца | **30 764** |

У базовых мер нет формата, доли показываются дробью. Для процентов: выделить меру →
«Средства меры» → кнопка **%**. На странице формат задаёт переключатель `Значение`.

**Не сходится — где искать:**

| Симптом | Причина |
|---|---|
| итог верный, строки источников пустые или одинаковые | нет связи `dim_source` → факт (шаг 4) |
| во всех месяцах одни и те же числа | нет связи `dim_month` → факт |
| итог примерно вдвое больше | Power BI связал факты между собой — удалить связь в представлении модели (шаг 0) |
| строка «(Пусто)» или нет строки «POS — Fenix» | ключ продукта не совпал с `dim_product` |
| визуал пуст целиком, хотя связи верны | фильтр или ось стоят на поле факта (`month_start`, `product_key`), а не справочника — заменить на `dim_month[Месяц]` / `dim_product[…]`; ключи фактов скрыть (шаг 4) |

Сошлось — обе матрицы выделить и удалить (Delete).

## Шаг 7. Страница «0 · Итог банка» — общие показатели

До страницы — шаг 5 для `Значение` (динамический формат): кликнуть меру → «Средства
меры» → «Формат» → «Динамический» → в строке формул `SELECTEDVALUE ( 'Показатель'[Формат], "#,0.0" )`.

1. «+» внизу → новая страница, двойной клик по ярлыку → `0 · Итог банка`.
2. «Визуализации» → «Матрица», растянуть на страницу.
3. Строки ← `Показатель[Раздел]`, затем `Показатель[Показатель]` (порядок важен);
   Столбцы ← `dim_month[Месяц]`; Значения ← `Меры[Значение]`.
4. «Фильтры» → **«Фильтры для этой страницы»** ← `dim_month[Последние 12]` → True.
5. Над матрицей — «Развернуть все на один уровень вниз» (две стрелки вниз).
6. Формат (кисть): промежуточные итоги по строкам — **выкл.**, по столбцам — **выкл.**;
   «Макет» → «Макет матрицы» → **«Компактный»** (в других версиях — «Ступенчатый»).

Все показатели в одном формате («9,111.0», доля «0.7») — динамический формат не
сработал: проверить выражение формата у `Значение` (список слева от строки формул →
«Формат»). Выражение верное, а формат один — заменить в матрице `Значение` на
`Значение (текст)` из `PBI_model.dax`.

**Проверка.** Шесть разделов, 20 показателей, 12 месяцев 2025-09 … 2026-08. Столбец
2026-08: остаток **1 521,6**, провизии **112,5**, покрытие **7,4 %**. «Заёмщиков с
остатком» и «Остаток на заёмщика» — **пусто**: номер заёмщика системный, между
источниками не складывается.

Итоги по столбцам выключены намеренно: для потока итог за 12 месяцев — сумма,
для остатка — последний месяц, для долей — доля за год. В одном столбце это
три разных смысла.

## Шаг 8. Страница «1 · По источникам»

Копия страницы 0, в строки третьим уровнем — `dim_source[Источник]`.
Итоги по строкам — **вкл.** только на уровне `Показатель`: строка показателя
даёт итог банка, под ней — источники. Ровно прежняя раскладка Excel: блок на
показатель, внутри источники, 12 месяцев в столбцах.

---

## Шаг 9. Страница «2 · По продуктам»

Строки: `Показатель[Показатель]` → `dim_product[Обеспечение]` → `[Группа]` → `[Продукт]`.
Раскрытие «+» по уровням.

**Проверка.** В `dim_product[Обеспечение]` не должно быть пустого значения. Пустое —
ключ из данных, которого нет в `dim_product`: новый продукт или новое значение поля.
Не прятать — дописать строку в `dim_product`.

## Шаг 10. Сноски

Текстовое поле внизу каждой страницы. Минимум, без которого цифры читаются неверно
(полный список — `POWERBI.md`, раздел «Сноски»):

- **провизии с 06.2026 неполны:** на S03 появились счета 1484 и 1485 (~58,7 млрд),
  формула провизий их не видит; смысл счетов уточняется у бухгалтерии;
- **S03:** выдачи прекращены с 04.2026; остаток сокращается на 27–33 млрд в месяц;
- **Fenix, 12.2025:** ~30 тыс. «закрытий» — выбытие портфеля, а не погашение;
  в «полностью погашено» не входит;
- **новый продукт Fenix:** низкая просрочка — возраст портфеля, а не качество;
- **заёмщики** на итоге банка не показываются — не складываются между системами;
- **средняя сумма выдачи и срок на итоге банка не читаются:** смешивают корпоратив и
  розницу (08.2026 — 45,2 млрд на 5 кредитов КБ и 1 700 розничных, «средняя» 28,9 млн).
  Смотреть на страницах 1–2; на странице 0 убрать или оставить с этой сноской;
- **04.2026:** «полностью погашено» 68 030 и фактический срок 70,8 мес — массовое
  закрытие карт S02 (57 866, средний срок 6,5 года), не движение портфеля.

## Шаг 11. Сохранение

`.pbix` — **только локально, в репозиторий не коммитится**: в режиме импорта он хранит
данные внутри себя (§2 корневого `CLAUDE.md`). В репозитории — SQL, DAX и этот файл.

Обновление каждый месяц: Главная → Обновить. Запросы сами берут последнюю дату
среза — править ничего не нужно. После обновления — шаг 6 заново: контрольные клетки
сдвинутся, но итог по источникам должен сходиться с итогом банка.
