# Сборка отчёта в Power BI — с нуля

Редакция 29.09.2026 — сборка заново, одним проходом. Прежняя редакция (шаги 8а, 8б, 9а,
вставки K1–K6) — в истории git; всё, что в ней было найдено на сборке, собрано в таблицу
«Если что-то не так» в конце.

**Что получится:** 6 фактов, 5 таблиц, 60 мер, 4 страницы. Около часа работы плюс время
обновления данных.

## Файлы

| Файл | Что это | Когда нужен |
|---|---|---|
| `PBI_fact_flow.sql` … `PBI_fact_vintage.sql` (6 шт.) | запросы фактов | шаг 1 |
| `PBI_tables.dax` | 5 таблиц для вставки | шаг 2 |
| `PBI_measures.dax` | все 60 мер одной вставкой + два контроля | шаг 4 |
| `PBI_model.dax` | **источник правды**: всё DAX с комментариями | правится только он |
| `build_paste.py` | собирает `PBI_tables.dax` и `PBI_measures.dax` из `PBI_model.dax` и проверяет модель | после любой правки DAX |
| `POWERBI.md` | почему модель такая; сноски для страниц | шаг 9 |

`PBI_tables.dax` и `PBI_measures.dax` руками не правятся. Правка — в `PBI_model.dax`, затем
`python build_paste.py`: он же проверяет, что каждый показатель имеет ветку в `Значение`,
каждая мера существует и каждый столбец факта есть на выходе своего SQL. Ошибка — файлы
не пишутся.

## Устройство модели

Звезда: факты в центре, справочники вокруг. Таблица `Показатель` ни с чем не связана — она
задаёт строки матриц, а мера `Значение` по имени строки выбирает нужную меру.

| Таблица | Роль | Зерно | Откуда |
|---|---|---|---|
| `fact_flow` | поток: выдачи, погашения | месяц × источник × продукт | SQL |
| `fact_stock` | запас: остаток, просрочка, провизии | месяц × источник × продукт | SQL |
| `fact_borrowers` | заёмщики по источнику | месяц × источник | SQL |
| `fact_default` | дефолт по правилу 90+ | месяц × источник × продукт | SQL |
| `fact_stage` | стадии 1–4, провизии по стадиям | месяц × источник × продукт | SQL (+ `CL_PORTFOLIO`) |
| `fact_vintage` | поколения выдач | когорта × продукт × возраст | SQL |
| `dim_month`, `dim_source`, `dim_product` | справочники | месяц / источник / продукт | DAX |
| `Показатель` | строки матриц: 54 показателя в 8 разделах | показатель | DAX |
| `Меры` | контейнер для 60 мер | — | DAX |

Месяц всюду — «конец месяца»: срез 1-го числа описывает предыдущий месяц.

## Шаг 0. Новый файл и две настройки

Файл → Параметры и настройки → Параметры → **Текущий файл → Загрузка данных**, снять:
- «Автоматически обнаруживать новые связи после загрузки данных» — иначе Power BI свяжет
  факты между собой и удвоит цифры;
- «Автоматическая дата и время» — скрытые календари не нужны, есть `dim_month`.

## Шаг 1. Шесть запросов

Для каждого файла:

1. Главная → Получить данные → **SQL Server**.
2. Сервер — ваш; база данных — `Dictionaries`; режим — **Импорт**.
3. **Дополнительные параметры** → «Время ожидания команды (в минутах)» — `30`;
   «Инструкция SQL» — файл **целиком**.
4. ОК → **Загрузить**. Переименовать запрос.

**SQL — только в окно «Инструкция SQL», не в строку формул Power Query.** Строка формул
хранит код Power Query; SQL там превращается в текст, и запрос перестаёт быть таблицей.

| Файл | Запрос | Столбцов | Примечание |
|---|---|---|---|
| `PBI_fact_flow.sql` | `fact_flow` | 23 | |
| `PBI_fact_stock.sql` | `fact_stock` | 14 | |
| `PBI_fact_borrowers.sql` | `fact_borrowers` | 3 | |
| `PBI_fact_default.sql` | `fact_default` | 8 | тяжёлый |
| `PBI_fact_stage.sql` | `fact_stage` | 15 | читает и `CL_PORTFOLIO` — нужен доступ к обеим базам |
| `PBI_fact_vintage.sql` | `fact_vintage` | 13 | |

**Проверка** (представление данных): число столбцов как в таблице; `month_start` —
тип «Дата»; `product_key` — «Текст»; у всех шести запросов значок таблицы, не `ABC`.

## Шаг 3. Связи, скрытие ключей, сортировка

**Связи.** Представление модели → Управление связями → Создать (или перетащить поле на поле).
Все — «один ко многим», фильтр в одну сторону, от справочника к факту. **16 связей:**

| Справочник | `fact_flow` | `fact_stock` | `fact_borrowers` | `fact_default` | `fact_stage` | `fact_vintage` |
|---|---|---|---|---|---|---|
| `dim_month[Date]` | `month_start` | `month_start` | `month_start` | `month_start` | `month_start` | — |
| `dim_source[l_source]` | `l_source` | `l_source` | `l_source` | `l_source` | `l_source` | `l_source` |
| `dim_product[product_key]` | `product_key` | `product_key` | — | `product_key` | `product_key` | `product_key` |

`fact_vintage` с `dim_month` не связан: у поколений ось — возраст, а не месяц.
`Показатель` и `Меры` ни с чем не связываются.

**Скрыть ключи фактов** (правый клик → Скрыть): `month_start`, `l_source`, `product_key`
во всех фактах и `snapshot_date` в `fact_stock`. Все показатели — меры, поэтому можно
скрыть факты целиком, кроме `fact_vintage[age_k]` и `fact_vintage[cohort_label]` — они нужны
на странице поколений.

**Сортировка.** Панель «Данные» → левый клик по **имени** столбца → вкладка «Средства
столбцов» → «Сортировать по столбцу»:

| Столбец | Сортировать по |
|---|---|
| `dim_source[Источник]` | `Порядок` |
| `dim_month[Месяц]` | `month_idx` |
| `dim_product[Обеспечение]` / `[Группа]` / `[Продукт]` | `П1` / `П2` / `П3` |
| `Показатель[Показатель]` | `Порядок` |

`Показатель[Раздел]` сортируется по алфавиту: номера разделов стоят в начале имени.

**Проверка:** «Управление связями» — 16 строк, все активны, ни одной между фактами,
ни одной «многие ко многим».

## Шаг 4. Все меры — одной вставкой

1. Слева значок **«Представление запросов DAX»** (DAX query view) → новый запрос.
2. Вставить `PBI_measures.dax` **целиком** → **Выполнить** (F5).
3. Внизу появятся две таблицы результатов — сверить с ожидаемым:

   | Контроль 1, 2026-08 | Ожидается |
   |---|---|
   | Общий остаток, млрд ₸ | 1 521,6 |
   | Покрытие провизиями | 0,074 |
   | Управленческий уровень просрочки | 0,093 |
   | Объём выдач, млрд ₸ / Количество выдач | 50,5 / 2 006 |
   | Карты: выдано | 228 |
   | Новые дефолты, шт / В дефолте, млрд ₸ | 1 473 / 64,4 |
   | Stage 3 + 4, млрд ₸ / Доля Stage 3 + 4 | 155,6 / 0,102 |

   | Контроль 2, 2026-07 | Stage 1 | Stage 2 | Stage 3 | POCI |
   |---|---|---|---|---|
   | млрд ₸ | 1 359,4 | 30,1 | 150,7 | 5,9 |

   На этом шаге меры ещё живут только в запросе — модель не тронута. Не сошлось — не
   добавлять, а искать причину (таблица в конце).
4. Сошлось → надпись над `DEFINE` **«Обновить модель: добавить новые меры»** → 60 мер
   появятся в таблице `Меры`.
5. Мера `Значение` → Средства меры → Формат → **Динамический** → выражение:
   ```dax
   SELECTEDVALUE ( 'Показатель'[Формат], "#,0.0" )
   ```
6. Скрыть служебную меру `_Остаток (сумма)`.

**Нет «Представления запросов DAX»** (старая версия Power BI Desktop): таблица `Меры` →
«Создать меру» по каждому блоку `MEASURE` из `PBI_measures.dax` (текст после
`MEASURE 'Меры'[Имя] =`), имя — как в скобках. 60 раз; контроль — на странице 0.

## Шаг 6. Страница «0 · Итог банка»

1. Визуализации → **Матрица**. Строки: `Показатель[Раздел]`, `Показатель[Показатель]`.
   Столбцы: `dim_month[Месяц]`. Значения: `Значение`.
2. Формат → Макет и стили → **«Компактный»**.
3. «Промежуточные итоги строк» → вкл., уровень ряда — **все**, положение — **«Сверху»**.
   Строка раздела останется пустой сама: мера на ней пуста.
4. «Промежуточные итоги столбцов» → «Метка итогов» → `12 мес`. Поток в этом столбце —
   сумма за 12 месяцев, запас — конец периода, доли — отношение за период.
5. Раскрыть на показатели: **правый клик по названию раздела → «Развернуть» → «Весь уровень»**
   (или третий значок над матрицей — раздвоенная стрелка). Не двойная стрелка вниз: она не
   раскрывает, а переходит на уровень ниже и теряет раздел.
6. Фильтр этого визуала по `Показатель`: снять «Заёмщиков с остатком» и «Остаток на
   заёмщика» — на итоге банка они не считаются.

**Проверка, 2026-08:** Общий остаток 1 521,6; Покрытие провизиями 7,4 %; Управленческий
уровень просрочки 9,3 %; Stage 3 + 4 155,6 и 10,2 %; Новые дефолты 1 473.

## Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| у запроса значок `ABC`, вкладка «Средства для работы с текстом» | SQL вставлен в строку формул | «Источник» → `= Sql.Database("<сервер>", "Dictionaries")` → шестерёнка → «Инструкция SQL» |
| запрос не дожидается | время ожидания | «Время ожидания команды» — 30 мин; сначала прогнать в SSMS |
| `InvalidUnconstrainedJoin` на всех матрицах | в визуале нет рабочей меры: сломана `Значение` или пропал факт | шаг 1 (столбцы), шаг 4 (меры) |
| «Не удается определить значение для „X“» | меры `X` нет — DAX принял её за столбец | `python build_paste.py` и повторить шаг 4; вручную — сверить имена буква в букву |
| итог примерно вдвое больше | Power BI связал факты между собой | удалить связь факт ↔ факт; шаг 0 |
| во всех месяцах одни и те же числа | нет связи `dim_month` → факт | шаг 3 |
| визуал пуст целиком | фильтр или ось на поле факта, а не справочника | ключи фактов скрыть, фильтры — по `dim_*` |
| все показатели в одном формате | не задан динамический формат `Значение` | шаг 4, п. 5 |
| клетки пусты, в углу матрицы «Источник» | матрицу перевели двойной стрелкой на уровень ниже | стрелка «вверх» до конца, затем «Развернуть → Весь уровень» |
| строки показателей пусты, числа только у источников | выключены промежуточные итоги строк | шаг 6, п. 3 |
| месяцы раньше 2025-09 | пропал фильтр «Последние 12» | шаг 5 |
| пустые строки источников под показателем | «Показывать элементы без данных» | шаг 7, п. 4 |
| пустое «Обеспечение» | ключ продукта из данных не найден в `dim_product` | строка в `PBI_model.dax` → `build_paste.py` → заменить `dim_product` |
| `Уровень новых дефолтов` пуст в одном месяце | нет прошлого месяца в `fact_stock` (первый месяц окна) | так и должно быть |
| «Stage 3 + 4» у карт — десятки на 16 млн ₸ | так и есть: стадию нашли десятки карт | — |
