# План: новые дефолты, Stage 3 + 4 и поколения по дефолту

Заведён 28.09.2026 по запросу автора: «новые дефолты в объёме и в количестве,
Stage 3 + 4 помесячно, уровень дефолта по поколениям — по продуктам и когортам».
По §6 корневого `CLAUDE.md` — структура, сбор, обработка и критерии **до** скрипта.
Разведочный `sql/DEF_0_default_field_audit.sql` метрик не считает, только отвечает,
на чём их можно строить.

Связан с `VINTAGE_PLAN.md`: рамка поколений (когорта, возраст, цензурирование,
доверительный интервал) — оттуда без изменений. Новое здесь — **исход «дефолт»**
вместо «была просрочка» и две помесячные метрики портфеля.

---

## Сильнейший контраргумент — первым

**В витрине нет ни стадии, ни надёжной глубины просрочки** (README, «Ограничения»).
Любой «дефолт», построенный на витрине, — **конструкция по правилу**, а не
классификация Банка. Она разойдётся с отчётностью по провизиям, и вопрос «почему
у вас Stage 3 не такой, как у расчёта провизий» будет задан первым. Поэтому:

1. Метрики этого плана называются **«дефолт по правилу ДФ-1»**, а не «Stage 3»,
   пока источник — витрина. Stage 3 + 4 — только из системы, которая стадию
   присваивает (развилка ДФ-5).
2. Сверка с официальной стадией на общей дате — обязательный контроль, а не
   украшение (§5 «Контроли»). Без неё правило не принимается.

Второй контраргумент — к поколениям: история `loan_account` — 21 срез
(01.2025 … 09.2026). Дефолт по сроку «90+» вызревает к возрасту 4–6 месяцев,
поэтому у когорт после ~04.2026 кривая дефолта будет почти пустой. Это свойство
окна, а не качества поздних когорт.

## 1. Структурный подход

Три метрики — один признак. Сначала определяется **состояние «в дефолте» на срезе**,
из него выводятся все три:

| Метрика | Что это | Из состояния |
|---|---|---|
| **Новые дефолты** (поток) | договоры, **вошедшие** в дефолт за месяц: количество и объём | переход «не в дефолте на срезе `t−1`» → «в дефолте на срезе `t`» |
| **Stage 3 + 4 / запас в дефолте** (запас) | договоры в дефолте на конец месяца: количество и остаток, доля от портфеля | состояние на срезе `t` |
| **Уровень дефолта по поколениям** | доля договоров когорты выдач, **хотя бы раз** вошедших в дефолт к возрасту `k` | накопленное состояние по возрастам |

**Единица наблюдения** — договор (развилка ДФ-2). **Месяц события** — по соглашению
отчёта: срез 1-го числа `t` описывает конец месяца `t−1` (как у запаса в `fact_stock`).

**Цензурирование.** Первый срез 01.01.2025 не даёт «нового» дефолта — не с чем
сравнить; ряд новых дефолтов начинается с 01.2025 (срез 01.02.2025). Договор,
уже бывший в дефолте на первом срезе, «новым» не считается никогда в окне — это
левое цензурирование, и оно занижает первые месяцы при ДФ-3 «повторный = новый».

## 2. Определение дефолта — чем располагаем

**Из документов Банка.** _Дополняется по результату поиска по `provisions_method/`,
`npl_limits/`, `nst_credit/` — абзац ниже будет заменён ссылками на пункты._

**Из международной практики** — чтобы развилки опирались на проверяемый источник, а
не на «представляется правильным» (§6):

| Источник | Что говорит |
|---|---|
| IFRS 9, B5.5.37 | опровержимая презумпция: дефолт не позже 90 дней просрочки |
| CRR, ст. 178(1) | дефолт — 90+ дней по существенному обязательству **или** маловероятность погашения (UTP); для розницы допускается уровень договора, а не заёмщика |
| EBA/GL/2016/07 | признаки UTP: списание, продажа с существенным убытком, вынужденная реструктуризация, банкротство; **испытательный срок** не менее 3 месяцев до выхода из дефолта, 1 год — после вынужденной реструктуризации |
| AFR, коды `STAGE_B` (`nst_credit/_archive/AFR_CODES.md`) | `4` — POCI, приобретённые или созданные кредитно-обесцененные; к стадии 3 относить предписано |

**Что из этого есть в витрине** — ответ даст DEF_0:

| Признак | Поле | Состояние |
|---|---|---|
| 90+ дней | `days_past_due_principal` | по S17 заполнен ровно там, где `la_account_1424 <> 0`; по S02 весь ноль; S01, S03 — **DEF_0 блоки 1–2** |
| списание | `loans`: S03 статус `I` + `l_actual_closure_date` | работает (`RPT_F`), только S03 |
| вынужденная реструктуризация | `restructuring_v2` | события есть; признака «вынужденная» и отмены нет (`canc_date` пуст на 100 %) |
| продажа / уступка | — | не отличается от погашения (Р-4: S17 12.2025 записан «Закрыт») |
| стадия, POCI | — | в витрине нет; DEF_0 блок 0б ищет ещё раз по всей схеме |

## 3. План сбора

| Что | Откуда | Период |
|---|---|---|
| состояние на срезе: дни, остаток, 1424 | `loan_account`, открытые счета (`la_status = N'Открыт'`) | срезы 01.2025 … 09.2026 |
| продукт, когорта, сумма выдачи | `loans` — `product_key` как в `PBI_fact_flow.sql` | когорты 12.2024 … |
| списание S03 | `loans`, статус `I`, `l_actual_closure_date` | 24 мес |
| реструктуризация | `restructuring_v2` — если войдёт в ДФ-1 | срезы окна |
| стадия банка | **вне витрины** — только при ДФ-5 (а) | общие даты |

**Связь** — `la_gid = l_gid AND la_source = l_source`, как в фактах Power BI.
**Дубли** — счёт на срезе один; если DEF_0 покажет иначе — агрегат по `la_gid`.
**Пропуск среза у счёта** — состояние не выдумывается: пропущенный срез — «не наблюдён»,
а не «не в дефолте».

## 4. План обработки

**Факты для Power BI** — по образцу существующих, один оператор без `GO`:

| Факт | Зерно | Колонки |
|---|---|---|
| `fact_default` | месяц × источник × продукт | `new_def_cnt`, `new_def_balance`, `in_def_cnt`, `in_def_balance`, `cured_cnt` |
| `fact_vintage` | когорта × продукт × возраст | `cohort_cnt`, `cohort_amount`, `ever_def_cnt`, `ever_def_amount`, `observed` — рядом с `ever_overdue_*` из `VINTAGE_PLAN.md` |

**Формулы:**

- доля в дефолте = `in_def_balance` / остаток портфеля того же среза (и по количеству);
- уровень новых дефолтов за месяц = `new_def_cnt` / договоры **не** в дефолте на `t−1`;
- годовой уровень дефолтов (опционально, для сравнения с PD) — по EBA/GL/2017/16:
  вошедшие за 12 месяцев / не бывшие в дефолте на начало 12 месяцев;
- поколения: `ever_def_cnt(k)` / `cohort_cnt` и то же в сумме выдачи; точки дальше
  наблюдаемого возраста не строятся.

## 5. Контроли — с известным ответом (Н22)

| Контроль | Ожидание | Не сошлось — значит |
|---|---|---|
| дефолт по дням ⊂ просрочка по 1424 | каждый счёт с 90+ имеет `la_account_1424 <> 0` | поле дней не про основной долг |
| списания S03 (`RPT_F`) | ≥ X % списанных были в дефолте на одном из срезов до списания | правило пропускает путь в списание |
| Р-4: S17, 12.2025 | ~30,7 тыс. закрытых с просрочкой — в запасе дефолта ноября | правило не видит выбывающий плохой портфель |
| сверка со стадией Банка | доля совпадений на общей дате | без этого правило не принимается (ДФ-5) |
| поколения | Σ `cohort_cnt` = Σ `issued_cnt` из `fact_flow` | когорта собирается не так, как поток |

Порог X и приемлемая доля совпадений со стадией — за автором (развилки ниже).

## Развилки — решает автор

| № | Развилка | Предложение | Альтернатива |
|---|---|---|---|
| ДФ-0 | приёмка поля дней | `days_past_due_principal` принимается, если в DEF_0 блок 2 у ≥ 90 % пар прирост = календарные дни, и mism в блоке 1 < 1 % от просроченных | иной порог; поле отвергнуто — дефолт только по событиям |
| ДФ-1 | правило дефолта | 90+ по `days_past_due_principal` **или** списание S03 | + реструктуризация из `restructuring_v2` (без признака «вынужденная» — перебор); только 90+ |
| ДФ-2 | единица | договор (CRR 178(1) допускает для розницы) | заёмщик — заражение по всем договорам заёмщика; для S01 естественнее |
| ДФ-3 | повторный дефолт | новый — только после ≥ 3 срезов вне дефолта (испытательный срок EBA/GL/2016/07); раньше — продолжение прежнего | каждый вход — новый; только первый вход в окне |
| ДФ-4 | объём нового дефолта | остаток на срезе входа | остаток на предыдущем срезе — до начисления просрочки |
| ДФ-5 | источник Stage 3 + 4 | (а) система провизий (IFRS9) — отдельное решение: контур выходит за «только витрину»; (б) до тех пор — запас в дефолте по ДФ-1 с подписью «не стадия» | только (б); только запрос в расчёт провизий |
| ДФ-6 | периметр поколений | как В-4: S03 + S17; S01 и S02 — нет | + S01 отдельно; + S02 по месяцу выпуска карты |

Развилки В-1 … В-4 из `VINTAGE_PLAN.md` остаются в силе; при согласии с ДФ-1
кривая «была просрочка» становится ранним сигналом, кривая дефолта — основной.
