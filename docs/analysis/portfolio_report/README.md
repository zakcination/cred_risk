# Контур `portfolio_report` — сегментный отчёт по кредитному портфелю

Заведён 23.09.2026. Ежемесячный управленческий отчёт по портфелю в разрезе **сегментации**,
а не продуктов. Единственный источник — **`Dictionaries.risk_analytics`**.

## Почему витрина, а не `CL_PORTFOLIO`

`AQR20xx_B1A/B1B/B3C_*` — замороженные регуляторные выгрузки циклов, **не месячные**.
Это записано в `sql/stage3_safezone_discovery.sql` как прямое предупреждение. Для
повторяющегося отчёта они непригодны по построению: снимок цикла — не поток.

---

## Архитектура: четыре слоя

Схема взята из отраслевого образца (корейский отчёт по автопортфелю) и проверена
на применимость к нашим данным.

| Слой | Что отвечает | Состояние |
|---|---|---|
| **Поток** | что вошло в портфель и что вышло | **строится** — `l_funding_date` заполнена на 100 % по всем четырём источникам |
| **Запас** | что лежит сейчас | строится — `loan_account` с фильтром по статусу |
| **Риск** | что портится | строится на `delinquency_bucket` (97,9 % заполнения) |
| **Разрезы** | где именно портится | частично, см. ограничения |

Ключевое открытие: **поток строится не сравнением снимков, а по датам внутри одного.**
`loans` историзована на одну дату (01.09.2026), но несёт `l_funding_date`,
`l_first_repayment_date` и `l_actual_closure_date` — вход и выход читаются без истории.

---

## Постоянный набор метрик

Прокатывается по каждому разрезу без изменений — на этом держится сравнимость:

> **EAD · переход 1 → 3 · доля 90+ · покрытие провизиями**

Четвёртая метрика сегодня **не считается** — см. ограничения.

---

## Отбор действующего договора

Источник правила — `dict_registry/status_map.csv`.

```sql
      (   (l.l_source = 'S01' AND l.l_loan_status = N'О')      /* CP1251 206 */
       OR (l.l_source = 'S02' AND l.l_loan_status = 'Account OK')
       OR (l.l_source = 'S03' AND l.l_loan_status = 'O')       /* латиница 79 */
       OR (l.l_source = 'S17' AND l.l_loan_status = N'О') )    /* CP1251 206 */
  AND l.l_actual_closure_date IS NULL
```

Два условия вместе, а не порознь. Даёт **541 416** договоров из 8 231 917 (6,6 %).

**Правило заведомо занижает портфель** примерно на 32 900 договоров неопределённого
статуса. Недобор виден при сверке с расчётом провизий, перебор — нет.

**Гомоглифы.** Латинская `O` (код 79) у S03 и кириллическая `О` (206) у S01 и S17
на экране неразличимы. Условие по источнику обязательно; общее `IN ('O', N'О')` —
источник ошибки, которая ничем себя не выдаёт.

## Ограничения, установленные аудитом

| Что | Состояние | Следствие |
|---|---|---|
| **Стадии 1/2/3** | в витрине **нет** ни одного поля | доля Stage 3 не считается |
| **Провизии по займам** | **нет**; есть только по гарантиям и условным обязательствам | покрытие не считается |
| **Размер предприятия** | `l_entrepreneur_category` — это ФЛ/ЮЛ, **не крупный/средний/малый** | сегменты **CORLAR, CORMED, RETSML** не размечаются |
| `entity` | нет | правило DISASS — но оно инертно (ТР18) |
| `f_inv` | нет | CORINV — но признак не проставлен ни разу (О3) |
| `b_lsboo` | **код связи**, не флаг: заполнен у 2 765 из 15,64 млн | RELATE = `IS NOT NULL`, не `= 1`. Коды не расшифрованы |
| `days_past_due` | заполнен на 16,9 % | просрочку считать по `delinquency_bucket` |
| `b_region` | 1 087 значений, 35 % пусто | разрез по городам не строится |
| `l_branch_code` | один код даёт до 17 названий | разрез по филиалам не строится |
| `l_financial_consultant` | только S03 и только 47,7 % | разрез по менеджерам — на половине одного источника |
| `l_first_repayment_date` | по S02 — **ноль** | FPD по картам не считается |
| `l_initial_fee` | практически только S17 | разрез по первоначальному взносу — один источник |
| `l_rate` | содержит название продукта, а не ставку | доходность не считается |

**Вывод по сегментации:** из тринадцати правил размечаются десять. Три корпоративных
упираются в отсутствующее поле размера предприятия, и вычислить его по ст. 24 ПК РК
нельзя — численность и доход в витрине отсутствуют (О2).
