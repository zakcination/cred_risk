# Витрина риск-метрик

Один документ со статусом всех метрик, встречающихся в нормативной базе Банка:
факт против лимита, зона, **длительность** нахождения в зоне, скорость приближения
за период / квартал / год, частота наблюдения и частота контроля, последствия
несоблюдения. Полочка витрины — нормативный документ.

БРМ, АО «Евразийский банк». Начато 19.08.2026.

## Зачем

Событие пропускается не из-за отсутствия метрики, а из-за трёх разрывов: контроль
реже наблюдения, отсутствие порога наблюдения ниже порога реагирования и неучёт
длительности. Витрина закрывает все три и одновременно даёт форму для граф 6, 9
и 10 Таблицы 2 приложения к Структуре отчёта по ВПОДК (установленный уровень,
случаи достижения и их длительность).

## Что здесь лежит

| Путь | Что это |
|---|---|
| `registry/metrics.csv` | Реестр метрик: полочка, код, формула, лимит, сигнальный уровень, счётчик длительности, частота данных и контроля, контур, владелец, пункт-источник, признак сверки значения |
| `registry/shelves.csv` | Полочки: документ, реквизиты, роль, владелец мониторинга |
| `registry/consequences.csv` | Последствия несоблюдения по уровням: что наступает, срок, норма, публичность |
| `build/showcase.py` | Движок: зоны, утилизация, скорость, срок до лимита, расстояние в сигмах, счётчики нормы, длительность, повторяемость. Самопроверка: `--selftest` |
| `build/render_showcase.py` | Рендер витрины в HTML (полочки, карточки, таблица последствий) |
| `data/observations_template.csv` | Шаблон фактов: `code;period;value` |
| `out/vitrina.html` | Собранная витрина |

```
python3 build/showcase.py --selftest        # самопроверка движка на фикстуре
python3 build/render_showcase.py --fixture  # витрина на демонстрационных значениях
cp data/observations_template.csv data/observations.csv   # заполнить фактами
python3 build/render_showcase.py            # витрина на данных банка
```

## Состав на 19.08.2026

50 метрик на четырёх полочках: лимиты главы 11 Нормативов № 85 (8), пруденциальные
нормативы № 85 (8), признаки ухудшения № 119 (26 — все количественные показатели
приложения 1 с типом «основной / вспомогательный» и регуляторной частотой
мониторинга приложения 2), заявление риск-аппетита (8 ключевых из 25).
Два значения помечены `verified=no` и до сверки в отчётности не используются.

Что считает движок по каждой метрике:

- зона (зелёная / жёлтая / красная) по лимиту и сигнальному уровню;
- утилизация лимита и запас в единицах метрики;
- скорость приближения за отчётный период, квартал и год;
- срок до пробоя при текущей скорости и расстояние до лимита в сигмах
  собственной волатильности метрики;
- **длительность**: месяцев подряд выше лимита, месяцев подряд вне зелёной зоны,
  число пробоев за 12 периодов;
- **счётчики нормы**: 6 месяцев подряд (№ 119), 3 из 6 (валютные лимиты, LCR),
  2 из 6 (ROA), 2 квартала подряд (CIR), строгий рост 7 точек (98-1, 98-2);
- разрыв «контроль реже данных».

## Правила ведения

1. **Частота контроля не реже частоты данных.** Движок сам помечает метрики,
   где контроль реже наблюдения, — это кандидаты на учащение.
2. **Порог наблюдения ниже порога реагирования.** Сигнальный уровень
   калибруется по волатильности метрики, а не назначается «на глаз».
3. **Длительность — величина того же ранга, что факт.** Часть последствий
   наступает именно от длительности, а не от величины отклонения.
4. **Пустая метрика — сигнал.** Несколько периодов без данных либо ровный ноль —
   повод проверить метрику.
5. **Значение без сверки с текстом документа не публикуется** (`verified`).
