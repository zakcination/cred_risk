# Реестр объектов `Dictionaries.risk_analytics`

Контур-справочник по **новой ветви** хранилища (mart). Заведён 01.09.2026.

Отвечает на вопрос: **что представляет собой конкретная таблица или колонка и чему её значение
равно на самом деле.** Организован по объектам, а не по вопросам сверки.

## Чем отличается от `risk_dwh_reconciliation`

| Контур | Ось | Отвечает на |
|---|---|---|
| `risk_dwh_reconciliation` | источник и вопрос сверки | сходится ли OLD с NEW и почему нет |
| **`dict_registry`** | **объект: таблица, колонка** | что означает это поле и можно ли им пользоваться |

`FINDINGS.md` контура сверки — **ground truth и первоисточник**. Здесь ничего не доказывается
заново: строки переносятся с прямой ссылкой на раздел, где факт установлен. Расхождение между
этим реестром и `FINDINGS.md` всегда решается в пользу `FINDINGS.md`.

## Железное правило пополнения

Раздел 4 корневого CLAUDE.md: **имена колонок берутся только из живого аудита
`INFORMATION_SCHEMA`, не из BI-канваса и не из памяти. Имя колонки ≠ семантика.**

Отсюда два следствия, которые нарушать нельзя:

1. **Ни одна строка не добавляется по названию поля.** Пока поле не встретилось в выгрузке
   схемы и его значения не посчитаны, его здесь нет.
2. **Семантика фиксируется только вместе с числом.** «Поле пустое» без доли заполнения —
   не факт, а впечатление.

Скрипт `DICT_A_schema_audit.sql` собирает инвентарь схемы. Он read-only, без PII, с MAXDOP 1
и трёхчастными именами — правила раздела 4.

## Состав

| Файл | Что |
|---|---|
| `OBJECTS.md` | Таблицы: назначение, ключи, зерно, историзация |
| `FIELDS.md` | Поля: факт, следствие, откуда факт |
| `DICT_A_schema_audit.sql` | Живой аудит схемы — источник имён |

## Чего здесь нет

Выводов о сверке, оценок качества mart в целом, рекомендаций автору mart. Всё это —
в `risk_dwh_reconciliation`. Здесь только паспорта объектов.
