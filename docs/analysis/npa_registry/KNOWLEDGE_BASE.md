# Единая база знаний ВНД и НПА для GPT

Состояние на 13.09.2026. Это единая точка входа для ответов по нормативным и внутренним
основаниям кредитного риска, провизий, риск-аппетита, SREP, НСТ и восстановления финансовой
устойчивости.

База не хранит исходные тексты конфиденциальных ВНД Банка. Она связывает стабильный код
документа, его реквизиты и редакцию, прочитанные пункты, карточки источников, выявленные
конфликты и предметные разборы. Публичные НПА сопровождаются ссылкой на официальный текст.

## 1. Что считать источником

| Приоритет поиска | Источник | Что в нём подтверждается |
|---:|---|---|
| 1 | [`REGISTRY.md`](REGISTRY.md) | идентификатор, полное название, реквизиты, редакция, статус, замена и официальная ссылка |
| 2 | [`CITED.md`](CITED.md) | конкретный прочитанный пункт, дословная выдержка либо место её воспроизведения, применённый контур |
| 3 | [`PACKAGE_1_NPA_VND.md`](../provisions_method/PACKAGE_1_NPA_VND.md) | карточки источников по провизиям, статусы подтверждения и матрица конфликтов НПА ↔ ВНД |
| 4 | [`provisions_method/README.md`](../provisions_method/README.md) | декомпозиция формул и вычислительного ядра `VND-05` и `VND-13` по пунктам и координатам файлов |
| 5 | Предметные документы из раздела 3 | вывод по конкретной задаче; не заменяет первичный источник |

Для машинного поиска те же сведения собираются без ручного копирования:

| Каталог | Единица строки | Назначение |
|---|---|---|
| [`catalog/sources.csv`](catalog/sources.csv) | документ | поиск по `source_id`, типу, статусу, редакции и официальной ссылке |
| [`catalog/clauses.csv`](catalog/clauses.csv) | документ × пункт | поиск по координате нормы, формуле или зарегистрированному выводу |
| [`catalog/open_questions.csv`](catalog/open_questions.csv) | незакрытый пробел | запрет GPT выдавать непроверенное правило за подтверждённое |
| [`COVERAGE.md`](COVERAGE.md) | контрольный отчёт | численность источников, пунктов и непокрытых ВНД |

CSV являются производными. При расхождении действуют `REGISTRY.md` и `CITED.md`; каталоги
пересобираются командой `python3 docs/analysis/npa_registry/build_catalog.py`.

`README.md`, аналитическая записка или расчёт не становятся нормативным основанием только
потому, что они находятся в репозитории. Основанием является НПА, IFRS, ВНД или документ
регулятора, идентифицированный в `REGISTRY.md`.

## 2. Обязательный порядок ответа GPT

1. Установить вопрос, периметр и дату, на которую требуется правило. Если дата не названа,
   явно использовать дату состояния базы — 13.09.2026.
2. Найти документ в `REGISTRY.md` по стабильному `source_id`.
3. Проверить статус и редакцию. Отменённый документ разрешено использовать только для
   исторического периода или для объяснения цепочки замен.
4. Найти применимый пункт в `catalog/clauses.csv` и сверить его с `CITED.md`. Если пункта
   там нет, проверить `catalog/open_questions.csv` и не приписывать документу
   формулировку по памяти: поставить `ОТСУТСТВУЕТ` или `ТРЕБУЕТ РЕШЕНИЯ`.
5. Для провизий дополнительно проверить карточку и конфликт в `PACKAGE_1_NPA_VND.md`.
6. Для ВНД проверить координату правила в предметном разборе. Если точной формулировки
   в репозитории нет, ссылаться на пункт/приложение и писать, что вывод взят из
   зарегистрированного разбора ВНД, а не цитировать предполагаемый текст.
7. При конфликте показать обе версии отдельно. Не выбирать приоритет самостоятельно:
   утверждённая Банком иерархия источников в базе отсутствует.
8. Каждый содержательный вывод завершить ссылкой на источник по формату раздела 4.

## 4. Обязательный формат ссылки

### Публичный НПА

```text
[KZ-ARRFR-061, п. 15, первая редакция, действует с 01.01.2026]
Официальный текст: https://adilet.zan.kz/rus/docs/V2500036994
Карточка и проверенные пункты: npa_registry/REGISTRY.md; npa_registry/CITED.md
```

В обычном ответе это оформляется компактно:

> Основание: `KZ-ARRFR-061`, п. 15, первая редакция, действует с 01.01.2026
> ([официальный текст](https://adilet.zan.kz/rus/docs/V2500036994),
> [реестр](REGISTRY.md), [проверенные пункты](CITED.md)).

### Внутренний документ Банка

```text
[VND-05, Приложение 4, п. 5, редакция файла 21.02.2024]
Оригинал: внутреннее хранилище Банка; в GitHub не размещается
Карточка: provisions_method/PACKAGE_1_NPA_VND.md
Разбор: provisions_method/README.md
Статус подтверждения владельцем: ОТСУТСТВУЕТ / ТРЕБУЕТ РЕШЕНИЯ
```

Нельзя давать внешнюю ссылку на конфиденциальный оригинал ВНД или создавать видимость, что
репозиторий содержит его полный текст.

### Аналитический вывод

```text
[Документальный вывод / Расчёт на данных / Гипотеза]
Источник: source_id, пункт; путь к предметному разбору, раздел
Ограничение: конфликт, дата среза, неподтверждённый владелец или отсутствие исходных данных
```

## 5. Шаблон ответа GPT

```text
Статус: ПОДТВЕРЖДЕНО / НЕ ПРИМЕНИМО / ОТСУТСТВУЕТ / ТРЕБУЕТ РЕШЕНИЯ

Краткий ответ:
...

Основание НПА:
- source_id, полное название, редакция и дата действия, пункт;
  официальная ссылка; ссылка на REGISTRY.md/CITED.md.

Основание ВНД:
- source_id, название, редакция файла, пункт/приложение;
  ссылка на карточку и предметный разбор; статус подтверждения владельцем.

Конфликты и ограничения:
- обе версии правила и владелец требуемого решения.
```

Если вопрос требует числа, формулы или решения, которых в источниках нет, GPT останавливает
вывод на статусе `ОТСУТСТВУЕТ` или `ТРЕБУЕТ РЕШЕНИЯ`; значение по умолчанию не подставляется.

## 6. Запрещённые подмены

- Не ссылаться на имя файла без `source_id`, пункта и редакции документа.
- Не выдавать аналитический пересказ за дословную норму.
- Не применять отменённый акт к текущей дате.
- Не скрывать конфликт между НПА и ВНД.
- Не считать отсутствие банковской БД препятствием для нормативного ответа; оно блокирует
  только подтверждение фактических значений и reconciliation.
- Не загружать в GPT исходные ВНД, клиентские данные, выгрузки Банка или иные материалы,
  запрещённые правилами конфиденциальности репозитория.

## 7. Текущие критичные разрывы

На 13.09.2026 база не позволяет назвать весь пакет провизий утверждённым Банком:

- не подтверждена владельцем иерархия IFRS 9 → НПА → учётная политика → ВНД;
- `VND-05` конфликтует с `KZ-ARRFR-061` по порогу индивидуальной оценки и cure period;
- для `VND-13` не подтверждено действующее внешнее основание после отмены № 170;
- не назначены владельцы правил и не получены даты их подтверждения;
- эталонные Excel/OLE-версии формул не закреплены hash и maker/checker;
- учётная политика Банка по IFRS 9 в реестре отсутствует.

Полный перечень решений — [`PACKAGE_1_NPA_VND.md`, §§ 4–6](../provisions_method/PACKAGE_1_NPA_VND.md).
